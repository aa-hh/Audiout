# AudioutPopoverUI

## Purpose

The menu-bar popover UI (pure AppKit), and the **one-surface host**: `AppSurfaceController` owns the single `ControlPanelWindowController` shell and swaps three screens through it (Mixer = the real popover panel, Groups, Settings) behind the header's tab-bar switcher. `PopoverController` owns the Mixer brain, builds the card stack, ingests `Device` snapshots via `update(devices:)`, and drives `GroupController`/`AppRoutingController`. Routing arithmetic lives in Core (see [../../AGENTS.md](../../AGENTS.md)); this folder only renders and turns clicks into controller calls. Shared row views live in [../AudioutSharedUI/](../AudioutSharedUI/). This target depends on `AudioutWindowUI` + `AudioutSettingsUI` (the surface composes their content) — neither may ever depend back on it.

Wizard visual/design spec: [dev/notes/wizard-v2-handoff/visual-spec-from-agents-md.md](../../../dev/notes/wizard-v2-handoff/visual-spec-from-agents-md.md).

## Rules

- Reacts only to `Device.connectionState` EDGES, never polling: a `→ .failed` edge auto-expands its diagnosis panel once per episode (`guess → diagnosed` is the same episode, no re-run), and does NOT drop the device from Selected Devices/a group — the backend re-kicks only on a genuine comeback, never a same-descriptor re-announce of a dead receiver.
- Diagnosis panels auto-drive off `.failed` edges: `openDiagnosisIDs` is the open intent, a user dismissal records into `dismissedDiagnosisIDs` for the current episode only, and a fresh `.failed` edge starts a new episode (clears the dismissal). "Try again" is a single-device re-kick (`GroupController.retryConnection`), never a membership edit or broad re-apply — the backend itself never emits `.connecting` for a `.failed` device except on a user-initiated attempt, so a dismissed panel can never be resurrected by background retries.
- The open-diagnosis intent is ALSO pruned against MEMBERSHIP, not just connection-state edges: `.failed` is sticky (deselecting a failed device produces no `→ .off` edge), so `handleConnectionTransitions` additionally drops both intent sets for any id that fails `wantsAudio(_:)`. This is the mirror of the keep-intent rule above, not a breach of it — that rule forbids a FAILURE from dropping the user's selection; this drops the failure REPORT when the USER drops the selection.
- Every delegate callback mutates then calls `rebuild()`; rows aren't mutated in place after a structural change, except the refreshers used for mid-open repaints.
- Collapse state is keyed by the exact card header string — collapse calls must pass the same title the card was built with. The device-type subsections ("This Mac" / "AirPlay Devices" / "Cast Devices" / "Bluetooth Devices") ride the identical `collapsedState(for:default:)` machinery under their own titles.
- A subsection collapses by animating its OWN clip's height, never by rebuilding — a `rebuild()` toggle set content to its final height instantly while only the surface glided, reading as judder. Rows live in a `SubsectionBody` clip on the shared `collapseRevealDuration`; the row MODEL must move synchronously even though the clip teardown is deferred (`toggleSubsection`), because `renderedDeviceOrder()` feeds the structural-change compare and the rail extents in the same turn.
- A collapsed SUBSECTION cuts the rail exactly as a collapsed CARD does: `updateRailRows` indexes the FULL `deviceSections()` order, never `renderedDeviceOrder()`, so a hidden device still gets a terminus dot at its subsection's header instead of silently shortening the rail. `setRailRows` points `BusRailOverlayView.deviceSection` at that subsection's own adapter. TRAP: `deviceSection` is `weak` — the adapter must be retained in `subsectionBodies` or it deallocates and the cut silently reverts to the card's.
- Two DISPLAY-only filters sit between the device snapshot and the rows: subsection collapse, and the Bluetooth CONNECTED-ONLY listing (`isBluetoothRowListed(_:)`, opt-in: `isAvailable`, an explicit session connect attempt, `wantsAudio(_:)`, or main-out membership). Neither touches selection/membership/routing. TRAP: the attempt gate is SESSION-SCOPED, never `connectionState != .off` — `.failed` never clears for a paired device, so a state-based clause would mint a permanent, undismissable row out of any failed attempt.
- Two rebuild flavors, not interchangeable: `rebuildForOpen()` resets collapse defaults, discarding this open's manual toggles; plain `rebuild()` preserves them.
- No `NSScrollView` — height flows through `preferredContentSize`, so the card stack must stay pinned top AND bottom in `PopoverPanelViewController.loadView` or Auto Layout collapses it to zero. **Surplus shield**: the popover sizes a wrapper (`view`); the required-`==` content chain hangs from `contentContainer` with only a required `<=` between the two, deliberately no pull-tight pin, and `fittingSizeSettled` measures `contentContainer`, never `view`. This is the only shape that survives an over-tall popover: a required `==` straight to the sized view forces Auto Layout to deform the content instead; a `<=`-only pin makes `fittingSize` return stale (non-minimized) heights; a soft `==` has no priority that beats both extremes at once. With the shield, overflow degrades to inert canvas below the last card and the rail stays anchored.
- `insertRow`/`removeRow` own the re-fit — callers must NOT add their own `panelContentDidChangeHeight`. `removeRow` defers its detach into an `NSAnimationContext` completion handler, so a caller-side re-fit would measure a row still in the tree about to leave, and nothing re-measures once it's gone — the popover stays taller than its content by one row's worth. Any future row primitive that mutates the stack must republish the size itself, from wherever the mutation lands.
- An inserted row reveals DOWNWARD by animating a CLIP HEIGHT (`RowClipView`, 0 → natural), never `isHidden` — animating `isHidden` lets `NSStackView` grant the row its full height on the first frame, so content arrives instantly while the window is still animating, violating the surplus shield from the wrong side (taller-than-surface is the one case it can't absorb). The reveal's START state must be LAID OUT before the animation begins (a `preferredContentSize` measurement commits every row below to its final position first) or there's nothing to animate toward. **Every collapsible element — inserted row, subsection, card body — shares ONE clock, `FoldAnimator`, one duration/curve, and animates a CLIP HEIGHT ONLY, never alpha.** Two independently-clocked animations (a clip constraint under `NSAnimationContext` plus a window resize under AppKit's own curve) drift out of phase — the fix is one animated value: `FoldAnimator` sets every active tween's constant, runs ONE layout + re-fit, then fires completions, per tick. Never `animator()`, `NSAnimationContext`, or `allowsImplicitAnimation` in a fold path — each reintroduces a second clock. A retarget continues from the tween's LIVE constant, never a rest height. Reduce Motion and `HeadlessRuntime` resolve all folds instantly and completely, since the driver ticks off the main runloop that headless test runs don't reliably spin.
- **The popover is the ONLY host of `PopoverPanelViewController`, in dev AND in the shipping `.app`.** `AIRPLAY_CONTROL_PANEL=1` (baked in by `scripts/make-app.sh`) re-homes **Groups** into `ControlPanelWindowController` and nothing else. Don't chase a popover-surface bug (row heights, the sync drawer, card collapse) into the panel shell's window geometry; `NSPopover` keeps its own top edge pinned to the status item and grows downward on its own.
- `ConnectionDiagnosisView` never touches `NSPasteboard`; the host writes on `onCopyDetails`.
- `selectedAppBundleID` is host-owned, transient. All three removal entry points (± footer, "Remove from list", Delete/Backspace) must funnel through `removeApp(bundleID:)`.
- Every card's add/remove control is the SAME primitive, `CardFooterView` (a leading ± `NSSegmentedControl` in a bottom strip, never a full-width button or inline control) — Applications takes both segments, OUTPUT DEVICES takes `showsRemove: false`. It is always the card's last row, added after all subsections, so a sync drawer opening under its own row can never land below it.
- Chrome never outranks content: device/app NAMES are the brightest text on the panel, a card's entire header line is one quiet legend voice, and subsection labels sit a step under that — so no card ever prints a title over the SLIDER column (a fader with its own `%` names itself), and a column title renders only when that column actually has rows under it.
- Engaged-control chrome (mute pill, sync chip, hover/selection washes) is ONE neutral tone, `Tokens.Color.engagedChrome`, varying only by alpha — never the system accent (themes a meaning-state with the user's arbitrary macOS setting) and never gold (gold means signal, so a gold mute states the opposite). The one deliberate holdout is `DeviceRowView.flashLayer`, the attention pulse, which IS a signal.
- A dimmed label must be dimmed BY something: `tertiaryLabel` is right for text belonging to a disabled control (the dimming IS the "can't touch this" signal) but wrong for live state text like the card note explaining why every row is inert — that stays `secondaryLabel`, or dimming the explanation reads as broken rather than dormant.
- **The panel is host-agnostic; the surface is its only host.** A host announces itself with exactly two calls — `surfaceDidShow()` / `surfaceDidHide()` — and assigns `surfaceResizer` to hear every size publish, which `applySurfaceResize(animated:whileApplying:)` runs; the surface uses it only to notice content taller than its fixed frame (logged once per open), never to resize; a `nil` resizer means no host is listening (pre-claim / headless). **The one visibility answer is `isEffectivelyShown`** (the host's flag, or `test_isShownOverride` headlessly) — never invent a second visibility source.
- **The surface CLAIMS the panel through `claimPanelForSurfaceHosting()` — the one handover door.** Every open of the Mixer screen must run the open ritual — `rebuildForOpen()` then the exact-fit republish — because hidden-means-idle (below) leaves everything stale on purpose.
- **The one-surface contract (`AppSurfaceController`):** one shell, three lazily-built screens, every swap through the shell's `setContent` — assigning `contentViewController` directly snaps the window to a 500×500 fallback. ONE frame for every screen (`SurfaceLayout.width` wide, height measured on each fresh show from the Mixer's exact fit, floored/capped, re-asserted after every `setContent` and pin flip, never animated or re-centred) — the Mixer decides the height even when Groups or Settings is the screen that opens. Content taller than the frame logs telemetry rather than clipping silently.
- **The launch splash is ORNAMENT**, shown only on the first surface open of a process, gated three ways: skipped under Reduce Motion, skipped in every `HeadlessRuntime` run, and its reveal is DEFERRED until `DiscoverySettleTracker` reports the device stream has quiesced (or a ceiling timer backstops a network that never settles) — the window fronts ONCE at the already-settled size. This is the cure for the open jump: AppKit resizes the shell window to the content controller's `preferredContentSize` DEFERRED (a synchronous `setFrame` is overridden a runloop later — verified live), so the window can only be fronted already-correct, never held at a wrong size while on screen.
- Nothing in the surface is user-resizable — `shell.setUserResizable(false)` runs once at construction; there is no per-screen drag memory.
- **The header is a real window-attached `NSToolbar`** (`SurfaceToolbarController`) — `.unified` style, `titleVisibility` hidden in both profiles, tabs as an `NSToolbarItemGroup`. **TRAP: the display mode must stay `.iconOnly`** — under any label-showing mode, macOS 26+ builds the group's picker WITHOUT its interactive expanded view, and the strip becomes an empty capsule with all three segments dead. Tab selection stays HOST-CONFIRMED: a tap only reports through `onSelectScreen`, and the group re-asserts the confirmed `selectedScreen` after the callback. The toolbar lives in this target, not the shell, since it names the three screens and the shell must stay content-agnostic.
- **Hidden means idle, deliberately**: `update(devices:)`, `applyRoutedAppRunning`, `setLocalFallbackActive`, `applyNoteSlot` and both level pushes all skip their work behind `isEffectivelyShown`. Nothing is lost — every open runs `rebuildForOpen()` over the state ingested meanwhile — whereas rebuilding anyway turned each backend event into a full hidden rebuild, which stormed under volume-key repeat. Don't "simplify" one of these gates away.
- `surfaceDidHide()` also drops what must not outlive a session: the transient app-row selection, and every meter's last reading (`resetLevel()` on `deviceRowsByID`, `mainOutRow` and `appRowsByBundleID`) so a reopen never shows a stale bar. Both calls drive `(backend as? MeteringControlling)?.setMeteringActive(_:)` via `onMeteringActiveChange`, so the backend pays for RMS only while a UI exists to show it to.
- `PopoverController.updateLevel(_ rms:, for id:)` is the live push path from `AppDelegate`'s `.level` handling; `test_pushLevel(_:for:)` is the same dispatch with no visibility gate, for headless snapshots/tests. Both route to `deviceRowsByID[id]?.setLevel(rms)` and, for the Main Out id, `mainOutRow.setLevel(rms)`. `updateAppLevel(_:for:)` mirrors it for the Applications card — an app level never feeds `mainOutRow`, which mirrors the selected DEVICE's level, not any one app's contribution.
- **Energize** is orchestrated here, drawing-only: `mainOutRow(_:didSelect:)` calls `beginEnergize(to:)` before `rebuild()`, posting the VoiceOver transition announcement always and — unless Reduce Motion is on — seeding `energizePendingIDs` with the selected members still `.off`. `refreshDeviceRows()` calls `reconcileEnergize()` first, which prunes the beat off members that have moved past `.off` and fires a one-shot settle announcement once the target stops moving. No timers — the fill rides the live `connectionState` progression.
- **The rail connect pulse fires from `update(devices:)`'s connected-member diff, never from the overlay's draws.** `lastConnectedMemberIDs` is the firing baseline and advances while the surface is hidden too, so a reopen can never fire one. A genuine join reaches the overlay through `panel.playRailConnectPulse`; an overlay SIZE change cancels an in-flight bead so it never flies a path against geometry that has since moved.
- **The live-removal undo is offered only when the click actually silences a room, and the facts are read BEFORE the edit** — `isLiveMainAudioRemoval` (member ∧ connected ∧ Main Audio spine armed) is computed before `setDeviceSelected` runs, since two of those three flip the instant it does. The offer is keyed by device id on the CONTROLLER, never the row, because the toggle can rebuild the whole card; it never outlives the surface.
- Every device-type subsection is HIDDEN entirely when it has no rows — never an empty grouping label — except Bluetooth, whose empty body IS the Connect affordance. Bluetooth rows are recency-ordered; the OUTPUT DEVICES "+" fronts a menu (save group / pair a Bluetooth speaker / connect an unlisted pairing) rather than a header button.
- **The SYNC surface is not Bluetooth-only** — the Mac's own row carries the identical chip/drawer/wizard (`showsSyncControls: device.isBluetooth || device.isLocalDevice`); only the STORE differs (`AppSettings.syncOffsetMs` vs `BTTrimStore`). **Reset alignment is a THIRD write shape besides "set a trim" and "keep a measurement": it DELETES** the stored entry — never `onSetBTTrim(0, …)`/`onSetLocalTrim(0)`, since "tuned" is decided by whether an entry EXISTS, not its value.
- **The align-by-ear tick is host-owned lifecycle, backend-owned audio**: one row at a time, ~30s auto-stop, and `popoverDidClose` always stops it. The tick's button lives inside `BTSyncDrawerView`, so collapsing the drawer must stop it too — a metronome ticking with no visible control is a bug. Trim edits cache in `btTrimsByID` (freshest-edit-wins) so a repaint can't revert a user's nudge.
- **At most ONE sync drawer is open at a time** — there is ONE reused `BTSyncDrawerView` instance, not one per row; `expandedSyncDeviceID` is the single owner. Mount/unmount ONLY through `insertRow`/`removeRow` — a drawer moving between rows must detach un-animated or two animation groups fight over one clip's height.
- **A live scrub applies to audio but must NOT persist.** `syncDrawer(_:didChangeTrimMs:committed:)` splits on `committed`: `false` writes audio only, `true` writes audio AND the JSON store — without the split a drag would rewrite the store dozens of times a second. "Not set" is decided by whether the store HOLDS an entry, never by the value being zero.
- The BT alignment card's intent (`btAlignmentPromptDeviceID`) survives popover close/reopen and must remount via `reconcileBTAlignmentPanels` — the backend's hold-silent outlives a click-away.
- The wizard is a SHEET (`presentAsSheet`) the popover cannot close under — AppKit refuses to close a host with an attached sheet. A run ends only via a view-driven exit (Stop/Done/Esc); Stop exists on every screen including the intro.
- `reconcileBTWizardLiveness` runs OUTSIDE the `isEffectivelyShown` gate — the one exception to hidden-means-idle, since a tucked-away surface still must react to the target speaker going away.
- The wizard previews through the backend's LIVE delta path, never an engine rebuild, so each answer lands with no dropout.
- A LATENCY run suspends the user's trim to 0 for the run's duration (latency and trim are the same linear delay term); Keep writes latency AND zeroes trim; every other exit restores the prior stored value.
- `BTAlignmentWizardSession`/`BTAlignmentPosterior` are DETERMINISTIC — no RNG — so identical answers always produce identical questions; `back()` refolds the belief from the flat prior rather than storing undo states.
- "Both at once" is EVIDENCE, not a shrug — the estimator is a monotonic staircase and cannot treat a non-monotonic answer as noise.
- The run stops when the 95% credible interval's half-width reaches 8 ms, never at a fixed answer count — there is no "percent complete" to report.
- The prior is FLAT even on the zero-click path — a stored measurement opens on the PROPOSAL screen, never as a seeded prior.
- `.unreachable` (belief piled at the range margin) and `.unsettled` (interval stopped narrowing) are opposite bow-outs and must stay distinguishable — only `.unsettled` offers "Set it by hand".
- TRAP: `performKeyEquivalent(with:)` is NOT a live path for unmodified keys — arrows/Space/Esc/Return are delivered via `keyDown` to the first responder; only ⌘Z (a modified key) goes through `performKeyEquivalent`. The view must claim first responder explicitly (`makeFirstResponder`, not `initialFirstResponder`, which AppKit skips if it declines).
- TRAP: "unmodified" is NOT `modifierFlags.intersection(.deviceIndependentFlagsMask).isEmpty` — AppKit stamps arrow keys with `.function`/`.numericPad`, both inside that mask. Use `heldModifiers` (command/option/control/shift only) instead.
- Tests must drive unmodified keys through a real `NSWindow.sendEvent` carrying AppKit's actual flags for that key, never `performKeyEquivalent` directly — that bypass is exactly how the dead arrow-key map shipped green twice.
- Colour rule: gold is the app's primary colour everywhere; `syncSignal`/`partySignal` are sanctioned ONLY inside this wizard.
- **The wizard needs TWO audible speakers, so it makes the second one audible itself — and puts the selection back.** `startBTAlignmentWizard` resolves a reference (the Mac's row first, else another audible member, else any available device) and selects it through `GroupController` if not already in the user's intent, recording it in `btWizardEngagedReferenceID`. `tearDownBTWizard` is the single funnel every exit runs through, so the release always lands in one place. With no possible reference, Start stays disabled.
- **A selected Bluetooth device that loses availability is DESELECTED here, on the edge** (off = unselected) — `update(devices:)` diffs availability against the previous snapshot and routes the loss through `GroupController.setDeviceSelected`. EDGE-only: a selection made on an already-greyed row survives. This is deliberately the OPPOSITE of the AirPlay keep-intent rule above — don't unify the two.
- **EQ never lives on the Mixer.** The popover carries no tone state or controls — "Equalizer…" (context menu or row icon) fires `onOpenEqualizer` and deep-links to the Groups detail pane. Don't re-add a chip or drawer here.
- One off-token type site is ledgered, not stray: 11pt bold `ConnectionDiagnosisView:121` (the failure headline); `Tokens.Font.detail` covers the 11pt regular voice beside it.

## Map

| Type | What it is |
|---|---|
| `AppSurfaceController` | One-surface host: shell + toolbar + three screens + pin. |
| `SurfaceSplashView` | The first-open-per-process branded hold over the mounted screen; pure ornament, absent under Reduce Motion and headless. Laid over the already-settled list; hold-then-cross-fade. |
| `DiscoverySettleTracker` | Debounces the device stream to decide when discovery has quiesced; the host defers the first-open reveal until it fires, so the window fronts once at the settled size. |
| `SurfaceScreen` | The three screens; tab order, glyphs, ⌘-keys. |
| `SurfaceToolbarController` | The window toolbar header: tab group, centered name, Pin, Quit. |
| `SurfaceScreenViewController` | Seats a hosted content controller below the toolbar strip. |
| `PopoverController` | Mixer orchestrator: cards, `Device` ingestion, host seams. |
| `PopoverPanelViewController` | Card container: build/collapse by header title. |
| `CardView` | Rounded module: header rows + collapsible body. |
| `RowClipView` | Per-row clip an `insertRow` row unfolds downward inside; its height is the animated dimension. |
| `FoldAnimator` | The one fold clock: drives every clip height directly and lays the panel out from it each tick. Lives in `AudioutSharedUI` (public, `FoldFollowing` protocol) — shared with Settings' Advanced disclosure. |
| `MainOutRowView` | System Audio "Main Audio" row — slider, mute, "Output" destination dropdown, under-name `LevelMeterView`, and the membership rail's `.origin` hook (rises in the left gutter and turns into the meter). |
| `ConnectionDiagnosisView` | "Couldn't connect" panel under a failed row. |
| `BTAlignmentPromptView` | First-mix alignment card under a held-silent BT row: three actions. |
| `BTAlignmentWizardView` | Wizard sheet content: a `BTAlignmentWizardSession`'s screens under the stage. |
| `AlignmentStageView` | The belief instrument: the live interval drawn as light. |
| `AlignmentPlateButton` | The wizard's plate control; hover tracking, keycap AX help. |
| `AlignmentPlateCell` | Drawing-only plate skin: bevel, rim, keycap chip. |
| `AlignmentWizardViewController` | Sheet content controller hosting the wizard (canvas + room spill); presented on the panel via `presentAsSheet`. |
| `GroupRowView` | Group's master row; built for the window, unused here. Its `draw(_:)` paints the same inset rounded active/hover pill as the `AudioutSharedUI` rows — its stack host provides no system row highlight. |
| `RunningAppInfo` | Snapshot of a running app for the add picker. |

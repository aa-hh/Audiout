# AudiouterSharedUI

## Purpose

AppKit row views shared by the popover (`AudiouterPopoverUI`) and the mixer window (`AudiouterWindowUI`) so both hosts render the same device row from one implementation. Views here are pure UI: controls route out through a per-view `Delegate` (or closure), never touching a backend, store, or `GroupController` directly. For the routing model these rows render, see [../../AGENTS.md](../../AGENTS.md).

SharedUI also now hosts shared WINDOW CHROME, not only row views: `ControlPanelWindowController` is the reusable sticky floating-panel shell the control-panel rollout unifies Groups/Settings/Setup onto (one panel, content swapped via `setContent(_:)`, behind `AIRPLAY_CONTROL_PANEL=1`). It knows nothing about groups, devices, or settings — callers own their own content `NSViewController` and push it in. T11 gave it a custom-drawn arrow "beak" tying it to the menu-bar status item, right-edge alignment, and an open/close fade — see the exception rule and `ControlPanelBackingView` below.

## Rules

- Views never read shared model state — hosts push a plain-value snapshot via `apply(...)`. `DeviceRowView` takes `selected` explicitly (membership lives in `GroupController`, not `Device`); `AppRowView` takes an isolated `Configuration`.
- Row geometry lives in `PopoverColumnGrid` (named constants, no magic numbers) — columns anchor to the row's *trailing* edge, so slider/status/trailing-control columns line up across sections despite different leading controls.
- Hover state is transient, separate from selection, reconciled via an app-local `.mouseMoved` monitor cleared on every `apply` — an `NSTrackingArea` alone never fires `mouseExited` for a bottom-most row with an untracked dead-zone below it.
- `DeviceRowView` computes `isInMenu` live from `enclosingMenuItem` to pick its drawing path and accessibility role — don't hardcode one path for both hosts.
- Each view exposes `test_*` hooks (`test_setVolume`, `test_toggleEnabled`, …) that must drive the exact same delegate path as the live control, since gestures can't be synthesized headlessly.
- The device row's trailing control is an `NSButton` checkbox under a "Selected" header (membership in "Selected Devices"), not an `NSSwitch`; the column is not "Enabled".
- `DeviceRowView.apply` takes `controllable` separate from `selected`: slider/mute enablement follows `controllable`, but the checkbox and the sublabel's "System" token follow `selected` alone.
- The popover header's icon buttons are stock `NSButton` (`bezelStyle = .smallSquare`) — no custom hover-button class exists here.
- `DeviceRowView` gets a `showsMeter: Bool = false` init param; the mixer window and `GroupRowView` never pass `true`, so they stay visually unchanged. The leading VU meter (`LevelMeterView`) is mounted only when `showsMeter`, positioned via `PopoverColumnGrid.firstElementLeading(indented:)` so icon columns still align with meter-less rows. `setLevel(_:)`/`resetLevel()` are no-ops when `showsMeter` is false; `test_meterLevel()` returns the last pushed level (`0` with no meter or after a reset).
- `LevelMeterView` is layer-backed, non-interactive (`hitTest` returns `nil`), single-color (`systemGreen`, no yellow/red ramp, no peak-hold). It exposes `setLevel(_ rms: Float)`, `reset()`, `static let columnWidth: CGFloat`, and a deterministic `test_setDisplayedLevel(_:)` hook that sets the displayed fill synchronously with no display link, for snapshots/tests. Ballistics (attack faster than decay) live in the pure `static func ballisticsStep(displayed:target:) -> CGFloat` so the animation curve is unit-testable without a live view.
- `PopoverColumnGrid.meterWidth` and `.meterToLeading` size the new leading meter column; `firstElementLeading(indented:)` computes where the icon/first control starts as `(indented ? indentedLeadingInset : leadingInset) + meterWidth + meterToLeading`, so meter and meter-less rows still line up on the same grid.
- `AppRowView` gets the same `showsMeter: Bool = false` init param and leading `LevelMeterView` as `DeviceRowView` (task T4); every existing caller (`PopoverController`'s `AppRowView()`) omits it and is visually unchanged. When shown, the meter anchors at the row's leading edge and the icon repoints off the meter's trailing edge + `PopoverColumnGrid.meterToLeading` — the same x `firstElementLeading(indented:)` already reserved. `setLevel(_:)`/`resetLevel()`/`test_meterLevel()` mirror `DeviceRowView`'s signatures; the per-app level signal (`BackendEvent.appLevel`) drives `setLevel(_:)` via `PopoverController.updateAppLevel`, never from `apply(_:)`.
- Known stability findings in this target carry `STABILITY(id)` inline markers — details and fix sketches in [../../../dev/notes/stability-audit-2026-07-18.md](../../../dev/notes/stability-audit-2026-07-18.md).
- `DeviceIcon` is the single resolution point for "what SF Symbol represents this device/group" — `DeviceIcon.resolve(_:default:)` falls back to the kind/group default when an override is `nil` or no longer resolves on this OS (`DeviceIcon.isValid`), so every row/detail/icon-well caller shares one staleness check instead of its own nil-check-plus-validate dance. `DeviceIconController` is the only place a per-device icon override is looked up or written (`AudiouterCore.DeviceIconStore` persists it); only the bare symbol name string is ever persisted, never a resolved image or a color.
- **`ControlPanelBackingView` is an APPROVED custom-drawn exception (T11)** to the "stock components only" house rule (root `AGENTS.md`), the same category as `AudiouterWindowUI`'s icon-well hover scrim: NSPanel has no built-in arrow/notch, so tying the control-panel shell visually to the menu-bar status item requires custom drawing. All of it is confined to this one view — nothing else in the shell hand-draws chrome.
  - **Two-window shell, not one.** The real content panel (`ControlPanelWindowController`'s `window`) keeps its `.titled`/`.closable` style mask bits UNCHANGED from T1 — `performClose(_:)` silently no-ops (no `windowWillClose`, no `onClose`) on a window whose style mask lacks `.titled`, verified empirically, and that timing is load-bearing for the "land home" contract and this file's own tests. Instead the panel is made VISUALLY borderless (transparent title bar, hidden close button, `isOpaque = false`, no shadow of its own, `isMovable = false`) and a second, purely decorative `NSWindow` (`backingWindow`, borderless, `ignoresMouseEvents = true`, attached via `addChildWindow(_:ordered: .below)`) sits behind it hosting `ControlPanelBackingView`, which draws the rounded bubble + beak and owns the shape-fitted shadow (`hasShadow = true` + `invalidateShadow()`). Because the decorative window ignores all mouse events, hosted content in the real panel is never shadowed by it — this is the "correct hit-testing" guarantee, not a hand-rolled hit-test dance in the content's own view tree.
  - **The panel's own content view controller is left completely alone** (`window.contentViewController === controller` still holds, exactly like T1) — the shell never wraps or reparents caller-owned content. The only touch is cosmetic: `setContent` gives the hosted view a layer, a corner radius matching the bubble's, and an opaque backdrop fill (needed because the panel itself is now transparent) — see the doc comment on `configureContentAppearance` for the one known limitation (that fill color is a snapshot taken at `setContent`/`show` time, not a live-tracking dynamic color; a mid-session system-theme flip while the SAME panel instance stays open without reopening can leave it briefly stale).
  - **`show(anchorRect:)` reads the panel's frame back AFTER `makeKeyAndOrderFront`, never before.** AppKit can silently re-constrain a window's position to `NSScreen.visibleFrame` the instant it's actually ordered on screen; positioning the backing window from a frame captured before that happens desyncs the beak from the panel (found by manual verification, not by the structural unit tests — they never check the backing window at all). The panel's own vertical clamp also reserves `ControlPanelBackingView.beakHeight` above itself for the same reason: without it, a panel anchored near the screen's top edge (the normal case — that's where the menu bar is) triggers exactly that silent re-constrain on the backing window alone, breaking lockstep.
  - **Open/close is a plain opacity fade**, not a slide or scale-from-anchor: a transform-based "grow from the beak" would also need to run on the HOSTED content's layer to stay in lockstep with the bubble, and that layer belongs to caller-owned content whose `isFlipped` state this shell doesn't control, so a translate could animate the wrong direction depending on it. The fade is flattened (skipped entirely) under `NSWorkspace.shared.accessibilityDisplayShouldReduceMotion`. The close side is explicitly best-effort: `onClose` must keep firing synchronously from `windowWillClose` exactly as in T1 (✕/Esc/performClose/the test suite all depend on that timing), so the real close is never deferred to let the fade finish — in a live app there's usually enough of an async handoff to the window server for it to read as a transition; in a fast/headless run it may not render at all. A fully guaranteed close transition would require deferring the real close, which was deliberately rejected rather than hacked around.

## Map

| Type | What it is |
|---|---|
| `DeviceRowView` | Shared device row: icon, name/sublabel, mute, slider, %, Selected checkbox; optional leading `LevelMeterView` via `showsMeter`. |
| `LevelMeterView` | Shared leading VU bar (single-color fill, ballistics-driven, non-interactive). |
| `StatusDotView` | On-icon connection-status badge driven off `Device.connectionState`. |
| `PopoverColumnGrid` | Shared column-geometry constants, including the leading meter column (`meterWidth`, `meterToLeading`). |
| `AppRowView` | Popover-only per-app row; owns its own selection highlight and hover wash. Optional leading `LevelMeterView` via `showsMeter`, driven by `BackendEvent.appLevel`. |
| `DeviceIcon` | Single resolution point (+ curated symbol list) for device/group icon names, with render-time fallback. |
| `DeviceIconController` | Loads/persists per-device icon overrides via `AudiouterCore.DeviceIconStore`; the only read/write path for them. |
| `ControlPanelWindowController` | Reusable sticky floating-panel shell (control-panel rollout): ACTIVATING `NSPanel`, `hidesOnDeactivate`, one-panel-at-a-time via `setContent(_:)`, `onClose` fires only on a real close, `show(anchorRect:)` right-edge-aligns under the menu-bar item (T11) and drives the decorative backing window in lockstep. |
| `ControlPanelBackingView` | The approved custom-drawn exception (T11): rounded bubble + beak triangle tying the shell to the status item, hosted in a separate click-through decorative window behind the real content panel. |

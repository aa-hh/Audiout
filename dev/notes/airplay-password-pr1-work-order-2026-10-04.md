# Work order: password-protected AirPlay receivers, PR 1 of 2

Scoped 2026-10-04 from the four `airplay-pin-password-*-2026-10-04.md` notes and the owner's rulings in the decision note.

### Goal

Let Audiout play to AirPlay receivers that ask for a password: AirPlay 1 digest password (`_raop` `pw=true`) and AirPlay 2 "Require Password" (`_airplay` `pw=true` / statusFlags bit 7). The vendored sender already runs both handshakes once it has a password; today nothing feeds it one, so the app shows "Password required … isn't supported yet". This PR feeds the password through the config shim, stores it in the Keychain per speaker, asks for it in a small sheet on the Mac and on the phone, and marks protected speakers with a lock. Apple TV on-screen code pairing (bits 3/9, `outputs_device_authorize`, key save/restore) is PR 2: this PR only surfaces that a speaker needs a code, and leaves hooks noted inline.

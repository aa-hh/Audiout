# Work order: ticket 02, only the owning app may release the root PTP helper

Worktree: `/Users/alechenderson/Projects/AirPlay Controller/.claude/worktrees/cr-02-ptp-helper-xpc-peer-check` (HEAD a14ff11f, clean, nothing uncommitted).

## Goal

The root daemon `ptp-helper` exits when any local process sends `{"release": true}` over its Mach service; repeating that kills the PTP clock for every PTP-only speaker. Make the daemon honour `release` only from a peer whose code signature matches the app that shipped it (same bundle identifier, same Developer ID team), using libxpc's own peer check so the helper stays libSystem-only. An ad-hoc build cannot be pinned, so such a build refuses every release and relies on idle exit.

## Decisions recorded

- Requirement literal (the template value in the plist), exactly:
  `identifier "__BUNDLE_ID__" and anchor apple generic and certificate 1[field.1.2.840.113635.100.6.2.6] and certificate leaf[field.1.2.840.113635.100.6.1.13] and certificate leaf[subject.OU] = "__TEAM_ID__"`
  This is the app's own designated requirement with the two build-specific values tokenised. New token: `__TEAM_ID__`.
- New env key: `AUDIOUT_PTP_PEER_REQUIREMENT`. Empty string = no requirement = refuse every release.
- The requirement is set on each accepted peer connection before `xpc_connection_resume(peer)`, once per peer (the header forbids repeats).
- Team ID comes from `CODESIGN_IDENTITY` via the sed above. Ad-hoc (`-`) or an identity with no `(TEAMID)` suffix renders an empty requirement and make-app.sh prints one line saying so.
- The sed that renders the requirement must use a delimiter other than `/` (not needed for the chosen literal, which has no `/`, but `|` keeps it safe); `"`, `[`, `]`, `=` are not special on sed's replacement side and need no XML escaping in a `<string>`.
- Alternative noted, not scoped: `xpc_connection_set_peer_team_identity_requirement(peer, "<BUNDLE_ID>")` would remove the Team ID plumbing entirely, but it is macOS 14.4+ and AirPlayEngine targets 14.0.

## Steps

1. `AirPlayEngine/Sources/ptp-helper/main.c`, `ptp_helper_mach_checkin()` (`:443-483`). Read `AUDIOUT_PTP_PEER_REQUIREMENT` once at the top next to `AUDIOUT_PTP_MACH_SERVICE`. If it is unset or empty, log once via `ptp_helper_logmsg` that no peer requirement is configured and every release request will be refused (idle exit still ends the process). Inside the listener handler, for each accepted peer and before `xpc_connection_resume(peer)`: when a non-empty requirement exists, call `xpc_connection_set_peer_code_signing_requirement(peer, requirement)`; treat a non-zero return as "no requirement" for that peer (log the return value once via `ptp_helper_logmsg`). Keep a per-peer boolean meaning "release allowed" that is true only when the call was made and returned 0. In the peer's event handler: if `xpc_equal(event, XPC_ERROR_PEER_CODE_SIGNING_REQUIREMENT)`, log via `ptp_helper_logmsg` that a peer failed the code-signing requirement and was ignored, then return. If the event is a dictionary with `release` true and release is not allowed for this peer, log once per peer (a `__block` flag captured by the handler block) that the release was refused because no peer requirement is in force, and ignore it. Only when release is allowed does the existing path (`main.c:473-474`) run unchanged.

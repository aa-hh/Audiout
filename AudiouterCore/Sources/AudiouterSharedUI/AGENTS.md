# AudiouterSharedUI

## Purpose

AppKit row views shared by the popover (`AudiouterPopoverUI`) and the mixer window (`AudiouterWindowUI`) so both hosts render the same device row from one implementation. Views here are pure UI: controls route out through a per-view `Delegate` (or closure), never touching a backend, store, or `GroupController` directly. For the routing model these rows render, see [../../AGENTS.md](../../AGENTS.md).

SharedUI also now hosts shared WINDOW CHROME, not only row views: `ControlPanelWindowController` is the reusable sticky floating-panel shell the control-panel rollout unifies Groups/Settings/Setup onto (one panel, content swapped via `setContent(_:)`, behind `AIRPLAY_CONTROL_PANEL=1`). It knows nothing about groups, devices, or settings — callers own their own content `NSViewController` and push it in. T11 gave it a custom-drawn arrow "beak" tying it to the menu-bar status item, right-edge alignment, and an open/close fade — see the exception rule and `ControlPanelBackingView` below.

## Rules

- Views never read shared model state — hosts push a plain-value snapshot via `apply(...)`. `DeviceRowView` takes `selected` explicitly (membership lives in `GroupController`, not `Device`); `AppRowView` takes an isolated `Configuration`.
- Row geometry lives in `PopoverColumnGrid` (named constants, no magic numbers) — columns anchor to the row's *trailing* edge, so slider/status/trailing-control columns line up across sections despite different leading controls.
- Hover state is transient, separate from selection, reconciled via an app-local `.mouseMoved` monitor cleared on every `apply` — an `NSTrackingArea` alone never fires `mouseExited` for a bottom-most row with an untracked dead-zone below it.
- `DeviceRowView` computes `isInMenu` live from `enclosingMenuItem` to pick its drawing path and accessibility role — don't hardcode one path for both hosts.
- Each view exposes `test_*` hooks (`test_setVolume`, `test_toggleEnabled`, …) that must drive the exact same delegate path as the live control, since gestures can't be synthesized headlessly.
- The device row's trailing control is an `NSButton` checkbox under a "Selected" header (membership in "Selected Devices"), not an `NSSwitch`; the column is not "Enabled".
- `DeviceRowView.apply` takes `controllable` separate from `selected`: slider/mute enablement follows `controllable`, but the checkbox and the sublabel's "System" token follow `selected` alone.
- The popover header's icon buttons are stock `NSButton` (`bezelStyle = .smallSquare`) — no custom hover-button class exists here.
- `DeviceRowView` gets a `showsMeter: Bool = false` init param; the mixer window and `GroupRowView` never pass `true`, so they stay visually unchanged. The Warm-Signal-v4 meter (`LevelMeterView`) lives UNDER THE NAME inside a vertical `identityStack` (row order name / meter / sublabel), shown (un-hidden) only on armed rows — the stack recentres its visible lines, so no manual name-offset juggling. `setLevel(_:)`/`resetLevel()` are no-ops when `showsMeter` is false; `test_meterLevel()` returns the last pushed level (`0` with no meter or after a reset).
- `LevelMeterView` is layer-backed, non-interactive (`hitTest` returns `nil`). It is a SHORT HORIZONTAL bar (`PopoverColumnGrid.meterUnderNameWidth × meterUnderNameHeight`, v4 §Call-1) whose fill WIDTH tracks the level, growing left→right. Its fill is the Warm Signal **position-fixed warm gradient** `ember → gold → caution` (spec §1/§3.3): a full-width `CAGradientLayer` revealed through a leading-anchored mask, so hues live at fixed track widths and only the mask width moves per frame. `caution` is the ceiling — **failure red never appears in a meter** (house rule 8). It exposes `setLevel(_ rms: Float)`, `reset()`, `static let columnWidth: CGFloat` (now the bar THICKNESS), and deterministic hooks `test_setDisplayedLevel(_:)` / `test_targetLevel` / `test_displayedLevel` / `test_gradientColors` (no display link). Ballistics (attack faster than decay) live in the pure `static func ballisticsStep(displayed:target:) -> CGFloat`; a zero-target-at-rest `setLevel` no-ops instead of spinning up a display link (energy rule).
- The **gold route-armed corner dot** (`RouteArmedDotView`, spec §3.3, S2) sits on the icon's bottom-right corner (the retired connection dot's `statusDotInset` position) in `DeviceRowView` AND `MainOutRowView`. It is PURE MODEL STATE, never RMS (R3): the row computes `routeArmed = (inActiveTarget ∧ connected ∧ !rowMuted ∧ !masterMuted) ∨ liveAppNames≠∅` in `apply` — the host passes `masterMuted:` and `inActiveTarget:` (membership vs the ACTIVE Main Out target; `nil` falls back to `selected`). Armed = `gold` disc + static `glow` halo; unarmed = the dark `dotSocket`. The arm transition blooms `ember → gold` (≤450 ms ease-out) only on a false→true transition after the first apply, on screen, Reduce Motion off — model layer stays settled, so `cacheDisplay` snapshots are deterministic. Hooks: `test_routeArmed`, `test_dotFillColor`, `test_dotHasGlow`, `test_dotIsBlooming`.
- **Mute channel** (S3, spec §3.4/§3.5): a muted row's mute button draws a filled accent PILL on the real `NSButton`'s backing layer (glyph NEVER swaps to a slash — locked decision; behavior/keyboard/VoiceOver untouched); its meter DRAINS via the existing decay ballistics (`setLevel(0)`, never a new animation; pushes while muted are coerced to 0); its dot goes dark (the predicate's unmuted term); and its sublabel gains a leading small-caps `MUTED ·` token (micro-label voice, `Tokens.Font.microLabel`) **only when a feed sublabel already exists** — never a standalone line, so row height never changes (R7). Master mute drains/darkens without the per-row token (the Main Out pill carries it). Row/Main-Out `accessibilityValue` composes `"muted"` / `"armed"` / `"playing here"` as the spoken equivalents.
- Warm-Signal-v4 §Call-1 re-homes the leading gutter from a meter column to the **membership rail's LEFT SPINE**. `firstElementLeading(indented:)` reserves that gutter as `(indented ? indentedLeadingInset : leadingInset) + busGutterWidth`, where `busGutterWidth` is DERIVED from the rail geometry (`railGutterCenterX + busNodeDiameter/2 + busNodeClearance − leadingInset`) — so widening `railGutterCenterX` / `busNodeClearance` (Alec's node-clearance refinement) reflows only the LEADING columns; VOLUME/OUTPUT are trailing-anchored and hold. The under-name meter is sized by `meterUnderNameWidth`/`meterUnderNameHeight`.
- `AppRowView` gets the same `showsMeter` init param and the same under-name `LevelMeterView` inside an `identityStack` as `DeviceRowView` (v4 §Call-1); the icon leads at `firstElementLeading(indented:)`, so app icons align with device icons. App rows carry NO bus node — the left gutter is reserved but empty, mirroring how device rows leave the trailing dropdown column empty. `setLevel(_:)`/`resetLevel()`/`test_meterLevel()` mirror `DeviceRowView`'s signatures; the per-app level signal (`BackendEvent.appLevel`) drives `setLevel(_:)` via `PopoverController.updateAppLevel`, never from `apply(_:)`.
- **Instruments reconcile accessibility-display changes LIVE**: `HaloRingView`, `RouteArmedDotView`, `WarmCanvasView`, and `LevelMeterView` observe `NSWorkspace.accessibilityDisplayOptionsDidChangeNotification` (workspace notification center, selector-based) because a mid-session Reduce Motion / Increase Contrast / Reduce Transparency toggle arrives NEITHER through `apply` nor (for Reduce Transparency) through `viewDidChangeEffectiveAppearance` — a new animated/token-colored instrument must do the same or it silently ignores the toggle until the next model push. Reduce-Motion reads go through a `test_reduceMotionOverride` seam (`nil` = live value) so headless tests can drive both sides of the toggle by posting the real notification.
- **Warm fader skin** (spec §5 "slider track/knob look"): the row volume sliders (`DeviceRowView`, `MainOutRowView`, `AppRowView`) wear `WarmFaderCell` — a drawing-only `NSSliderCell` subclass overriding ONLY `drawBar`/`drawKnob` (tracking, keyboard, scroll-wheel, `isContinuous`, VoiceOver, focus ring all stock; the cell swap happens FIRST in `buildSubviews` so the min/max/target/action config after it lands on the new cell). It draws the flat recessed `well` trough (`faderTrackHeight` ≈ 5 pt, `faderRim` rim + drawn inner top shade — no layers), the gold gradient fill (dim end = `ember` pre-blended halfway toward `gold` so the low-value end clears the trough) ONLY while route-armed ∧ enabled — the EXACT §3.3 predicate the row's `RouteArmedDotView` renders (one armed truth, two instruments; `AppRowView` hosts no dot and uses its spec-§5.1 routed ∧ running equivalent) — a hue-neutral `ringConnected` fill otherwise (dimmed to `faderDisabledAlpha` when disabled), and a rounded-rect `faderThumb` thumb (≈10×17 pt, ≥3:1 vs canvas AND trough in both themes — measured ratios on the token; derived darkened outline, 1 px top highlight). All colors resolve through `Tokens` at draw time, so light/dark, Increase Contrast, and the accent dial (under `.systemAccent` the engaged fill becomes `controlAccentColor` + its ×0.55 companion) land for free; drawing is steady-state and byte-deterministic under `cacheDisplay`. Hooks: per-row `test_isFaderEngaged` / `test_hasWarmFaderSkin`, plus `DeviceRowView.test_fireSliderAction(settingValueTo:)` (real AppKit target/action dispatch, not the delegate shortcut) and `test_sliderConfiguration`. `GroupRowView`'s master slider and Settings' connect-volume slider deliberately stay stock.
- The device row's VoiceOver contract is ONE composed announcement: label = identity + membership + volume + connection clause, value = the live-signal words (`muted` / `armed` / `playing here`), hint = the blocked-row refusal reason — each channel spoken exactly ONCE, never duplicated across label/value, and the membership clause uses the BUS vocabulary ("in main audio") on `showsBus` rows so it matches the checkbox's own label.
- Known stability findings in this target carry `STABILITY(id)` inline markers — details and fix sketches in [../../../dev/notes/stability-audit-2026-07-18.md](../../../dev/notes/stability-audit-2026-07-18.md).
- `DeviceIcon` is the single resolution point for "what SF Symbol represents this device/group" — `DeviceIcon.resolve(_:default:)` falls back to the kind/group default when an override is `nil` or no longer resolves on this OS (`DeviceIcon.isValid`), so every row/detail/icon-well caller shares one staleness check instead of its own nil-check-plus-validate dance. `DeviceIconController` is the only place a per-device icon override is looked up or written (`AudiouterCore.DeviceIconStore` persists it); only the bare symbol name string is ever persisted, never a resolved image or a color.
- **`ControlPanelBackingView` is an APPROVED custom-drawn exception (T11)** to the "stock components only" house rule (root `AGENTS.md`), the same category as `AudiouterWindowUI`'s icon-well hover scrim: NSPanel has no built-in arrow/notch, so tying the control-panel shell visually to the menu-bar status item requires custom drawing. All of it is confined to this one view — nothing else in the shell hand-draws chrome.
  - **Two-window shell, not one.** The real content panel (`ControlPanelWindowController`'s `window`) keeps its `.titled`/`.closable` style mask bits UNCHANGED from T1 — `performClose(_:)` silently no-ops (no `windowWillClose`, no `onClose`) on a window whose style mask lacks `.titled`, verified empirically, and that timing is load-bearing for the "land home" contract and this file's own tests. Instead the panel is made VISUALLY borderless (transparent title bar + hidden title, `isOpaque = false`, no shadow of its own, `isMovable = false`) — but the standard CLOSE button is kept VISIBLE as the panel's one close affordance (an anchored surface that does not dismiss on click-out needs an obvious way out); miniaturize/zoom are hidden. Escape closes too, wired deterministically via `ControlPanelPanel.cancelOperation(_:)` → `performClose(_:)` rather than incidental default behavior. A second, purely decorative `NSWindow` (`backingWindow`, borderless, `ignoresMouseEvents = true`, attached via `addChildWindow(_:ordered: .below)`) sits behind it hosting `ControlPanelBackingView`, which draws the rounded bubble + beak and owns the shape-fitted shadow (`hasShadow = true` + `invalidateShadow()`). Because the decorative window ignores all mouse events, hosted content in the real panel is never shadowed by it — this is the "correct hit-testing" guarantee, not a hand-rolled hit-test dance in the content's own view tree.
  - **The panel's own content view controller is left completely alone** (`window.contentViewController === controller` still holds, exactly like T1) — the shell never wraps or reparents caller-owned content. The only touch is cosmetic: `setContent` gives the hosted view a layer, a corner radius matching the bubble's, and a TRANSPARENT (not opaque) background. The transparency is deliberate: the panel is transparent and the backing bubble already fills a LIVE warm `Tokens.Color.canvas` (Warm Signal §5.4, W8 — bubble, beak, and content pane read as ONE warm shape, light and dark), so leaving the content transparent lets that live fill show through — content that paints no opaque background of its own (Groups' split-view content pane) then adapts to dark/light as one with the sidebar, while content that paints its own adaptive background (Settings' `NSVisualEffectView` root) simply covers it (intended per §5.4). An earlier opaque `windowBackgroundColor.cgColor` fill here was a frozen snapshot that couldn't track a theme change — that was the dark-mode "half-render" (light content pane, dark sidebar); see `configureContentAppearance`.
  - **`show(anchorRect:)` reads the panel's frame back AFTER `makeKeyAndOrderFront`, never before.** AppKit can silently re-constrain a window's position to `NSScreen.visibleFrame` the instant it's actually ordered on screen; positioning the backing window from a frame captured before that happens desyncs the beak from the panel (found by manual verification, not by the structural unit tests — they never check the backing window at all). The panel's own vertical clamp also reserves `ControlPanelBackingView.beakHeight` above itself for the same reason: without it, a panel anchored near the screen's top edge (the normal case — that's where the menu bar is) triggers exactly that silent re-constrain on the backing window alone, breaking lockstep.
  - **Open/close is a plain opacity fade**, not a slide or scale-from-anchor: a transform-based "grow from the beak" would also need to run on the HOSTED content's layer to stay in lockstep with the bubble, and that layer belongs to caller-owned content whose `isFlipped` state this shell doesn't control, so a translate could animate the wrong direction depending on it. The fade is flattened (skipped entirely) under `NSWorkspace.shared.accessibilityDisplayShouldReduceMotion`. The close side is explicitly best-effort: `onClose` must keep firing synchronously from `windowWillClose` exactly as in T1 (✕/Esc/performClose/the test suite all depend on that timing), so the real close is never deferred to let the fade finish — in a live app there's usually enough of an async handoff to the window server for it to read as a transition; in a fast/headless run it may not render at all. A fully guaranteed close transition would require deferring the real close, which was deliberately rejected rather than hacked around.

## Map

| Type | What it is |
|---|---|
| `DeviceRowView` | Shared device row: icon, name/sublabel, mute, slider, %, Selected checkbox; optional leading `LevelMeterView` via `showsMeter`. |
| `LevelMeterView` | Shared under-name VU bar (short horizontal, warm `ember → gold → caution` gradient fill, ballistics-driven, non-interactive). |
| `MembershipBusView` | The membership checkbox's DRAWING-only skin: the LEFT-SPINE rail + node (member/connecting/pending/failed/nonMember/blocked/origin), drawn per-row for cross-row continuity. Non-interactive — the real `NSButton` stays the control. |
| `HaloRingView` | Connection **halo ring** drawn around the device icon, driven off `Device.connectionState` (off → none · connecting/reconnecting → dashed breathing · connected → solid `ringConnected` · failed → solid `failure`). Replaced the retired corner status-dot view (spec §3.2); that corner position now hosts `RouteArmedDotView`. |
| `RouteArmedDotView` | The **gold route-armed corner dot** (spec §3.3): pure model-state "route armed & held" lamp on the icon's corner — gold + static glow when armed, dark `dotSocket` otherwise; ember→gold bloom on arm (settled model layer, snapshot-deterministic). |
| `PopoverColumnGrid` | Shared column-geometry constants, including the left rail gutter (`railGutterCenterX`, `busNodeClearance`, `busGutterWidth`, `busNodeRailGap`, `busDetourBulge`), the under-name meter (`meterUnderNameWidth/Height`) and the warm fader geometry (`faderTrackHeight`, `faderThumbWidth/Height`, …). |
| `WarmFaderCell` | The Warm Signal fader skin (spec §5): drawing-only `NSSliderCell` swap on the row volume sliders — recessed `well` trough with `faderRim` rim, gold gradient fill (ember-blend dim end) iff route-armed, rounded-rect `faderThumb` thumb; behavior/AX all stock. |
| `AppRowView` | Popover-only per-app row; owns its own selection highlight and hover wash. Optional leading `LevelMeterView` via `showsMeter`, driven by `BackendEvent.appLevel`. |
| `DeviceIcon` | Single resolution point (+ curated symbol list) for device/group icon names, with render-time fallback. |
| `DeviceIconController` | Loads/persists per-device icon overrides via `AudiouterCore.DeviceIconStore`; the only read/write path for them. |
| `ControlPanelWindowController` | Reusable sticky floating-panel shell (control-panel rollout): ACTIVATING `NSPanel`, `hidesOnDeactivate`, one-panel-at-a-time via `setContent(_:)`, `onClose` fires only on a real close, `show(anchorRect:)` right-edge-aligns under the menu-bar item (T11) and drives the decorative backing window in lockstep. |
| `ControlPanelBackingView` | The approved custom-drawn exception (T11): rounded bubble + beak triangle tying the shell to the status item, hosted in a separate click-through decorative window behind the real content panel. Filled with the warm `canvas` token (§5.4, W8), resolved live per repaint + repainted on appearance flips. |
| `Tokens` | The root AGENTS.md's one sanctioned custom-palette exception: `Tokens.Font`, `Tokens.Layout`, `Tokens.Material` are pure forwarding aliases to existing semantic `NSFont`/`PopoverColumnGrid`/`NSVisualEffectView.Material` values. `Tokens.Color` is MOSTLY the same (semantic `NSColor` aliases) but, as of warm-signal-v2, ALSO holds the first real custom values: the warm surface ladder + hairline (`canvas`, `canvasHi`, `panel`, `raised`, `well`, `hairline`, spec §1), each a live appearance- + Increase-Contrast-resolving `NSColor(name:dynamicProvider:)` with a documented contrast rationale inline. Any future custom color added here must do the same. |
| `WarmCanvasView` | The Warm Signal canvas (spec §5.1): a plain, always-opaque, layer-backed `NSView` painting the `canvasHi → canvas` vertical gradient + a deterministic grain texture (dark only), flattening to the flat `canvas` color with no grain under Reduce Transparency/Increase Contrast. Introduced by warm-signal-v2 to replace `PopoverPanelViewController`'s old vibrant `NSVisualEffectView` background; reusable by later warm-canvas surfaces (Groups content pane, §5.3). `WarmSignalGrain` (same file) is the grain tile generator — deterministic by construction (pure coordinate hash, no RNG) so snapshot PNGs stay byte-identical run-to-run. |

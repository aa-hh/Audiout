# Audiouter Accessibility Audit — 2026-08-01

**Standard applied:** [`A11Y-GOLD-STANDARD.md`](A11Y-GOLD-STANDARD.md) v1.0 (WCAG 2.2 AA
via WCAG2ICT + EN 301 549 + Apple platform layer).
**Method:** seven parallel specialist static audits (popover surface · shared row
instruments · Groups window · Settings window · app shell & entry · visual system
cross-cutting · onboarding), each reading the rubric, the folder AGENTS.md, the
full scope sources, and the existing test suites — followed by a lead
verification pass that spot-checked every report's load-bearing claims against
source before acceptance. Static `[S]`/instrumented `[T]` passes only; the `[L]`
live pass is owed as the consolidated checklist in §5.

**Headline verdict:** the codebase's accessibility *baseline* is genuinely strong
— composed VoiceOver row contracts, systematic Reduce Motion gating, measured
contrast tokens, hand-rolled keyboard support on custom wells, real AX regression
tests. The gaps are not "accessibility was forgotten"; they are **systemic
omissions of the dynamic half** of accessibility: nothing announces, focus is
never seeded or preserved, labels go stale after state changes, and several
AX-vs-visible-text contracts drift. Because the causes are systemic, the fixes
are too — a small number of shared mechanisms close the majority of findings
(see themes below and `docs/plans/PLAN-ACCESSIBILITY.md`).

No finding was graded Blocker outright; two Majors sit at the Blocker border for
keyboard-only users (GRP-01, POP-03+SHL-03 combined). Findings marked
**LEDGERED** re-surface the standard's §5 deliberate exceptions as required —
they are reported, not re-litigated.

## 3. Findings by surface

Format: ID · severity · criteria · confidence. Locations are repo-relative.
"Why" is the mechanism and the affected user; "Fix" is the concrete remediation
(root-cause preferred). Findings within a surface are ordered most-severe-first.

### 3.1 Settings window (SET)

**SET-01 · Major · A5, 4.1.2, 1.3.1 · Confirmed-in-code**
Sliders never expose their value in human units.
`AudiouterCore/Sources/AudiouterSettingsUI/AudioSettingsViewController.swift:242-257`
(connect volume), `:581-596` (sync offset). Both `NSSlider`s get labels but no
`accessibilityValueDescription` (none exists repo-wide); the visible "40%"/"−120 ms"
labels are unassociated text fields. VoiceOver speaks raw/percent-of-range values:
for sync offset (−500…+500 ms) the spoken value carries no unit or sign semantics —
the entire point of the control (ahead vs behind) is inaudible; for connect volume
the range floor is 5, so a range-percent reading is numerically wrong vs the
visible "40%". **Fix:** one shared `bind(slider:to:)` helper setting
`setAccessibilityValueDescription` from the same formatter that writes the visible
label, at init and on every change; AX increment/decrement then announces
correctly for free.

**SET-02 · Major · A9, 2.5.3, A1 · Confirmed-in-code**
Accessibility labels override and contradict visible button titles.
`AudioSettingsViewController.swift:459` (visible "Apply Settings"/"Apply &
Reconnect", AX "Apply audio buffer change"), `:702-706` (visible "Add app…", AX
"Add excluded application"). Voice Control resolves "Click ⟨visible text⟩"
against the AX label — both fail. The Apply label is also static while the
visible title toggles, so VoiceOver users are never told the armed action will
reconnect speakers with an audible 3–5 s gap. **Fix:** delete both
`setAccessibilityLabel` calls — a titled `NSButton`'s AX name is its title and
tracks the retitle automatically; move longer phrasing to `setAccessibilityHelp`.

**SET-03 · Major · A4, 4.1.3, E2 · Confirmed-in-code**
Buffer Apply lifecycle entirely unannounced. `AudioSettingsViewController.swift:494-501`
(arming), `:531-562` (status transitions), `:557-561` (2.5 s transient hide). Picking
a buffer value only *arms* Apply (a VoiceOver user who picks a value and closes
the window silently loses the change); "Reconnecting speakers…" appears unannounced
while audio audibly drops; the completion caption hides after 2.5 s — usually before
a VoiceOver user can reach it. **Fix:** announce the armed transition ("Buffer set
to N ms — press Apply & Reconnect to use it"), the reconnect (high priority), and
the completion; keep the completion caption until the next change.

**SET-04 · Major · 1.3.1, A7, A4 · Confirmed-in-code**
The LIVE hint-line pattern is visually adjacent only. `SettingsForm.swift:50-58`,
`:64-113`; rewrite sites `AppearanceSettingsViewController.swift:135`,
`AudioSettingsViewController.swift:294, :358, :521`. The AGENTS-locked pattern
("consequential controls carry a LIVE hint line") is the panes' entire explanation
layer, and it is invisible to assistive tech: free-standing text fields, no
`accessibilityHelp`, no announcement on rewrite. A VoiceOver user on the
connect-volume slider never hears "a very loud start — may startle" (a genuine
safety consequence). **Fix (root):** `SettingsForm.row` sets
`control.setAccessibilityHelp(subtitle)`; one pane-side `setHint(_:on:announce:)`
helper writes the label *and* the help, announcing when called from a value-change
path — all four rewrite sites route through it.

**SET-05 · Major · B3, G3, B7, A4 · Confirmed-in-code (landing spot needs live confirm)**
Every list mutation and tab switch strands keyboard/VoiceOver focus; removals are
unannounced. `AudioSettingsViewController.swift:629-644` (`rebuildList` full
teardown), `:776-786` (add/remove); `SettingsWindowController.swift:459-471`
(tab switch never re-seeds; no `makeFirstResponder` in the module). A keyboard
user pressing Space on "Remove Spotify" has the first responder deallocated under
them — Tab restarts from the pane top after every mutation; no announcement
confirms the destructive completion. **Fix:** after `rebuildList()`, promote the
same-index remove button (clamped; Add when emptied) and announce "Removed ⟨app⟩";
on tab switch, make the incoming pane's first key view first responder.

**SET-06 · Major · B4, 2.4.7, B6 · Needs-live-confirm**
Theme tiles likely have no visible keyboard focus indicator.
`AppearanceSettingsViewController.swift:248-366` (`ThemeTileButton`: fully custom
`draw(_:)`, `isBordered = false`, cell content empty, no `drawFocusRingMask`).
The system focus ring derives from the cell's mask — empty content + no bezel is
the classic recipe for an absent ring, on the control where Space changes the
whole app's appearance. **Fix:** override `focusRingMaskBounds` + `drawFocusRingMask()`
to trace the tile's ring rect.

**SET-07 · Major · E2, 3.3.1/3.3.3, A4 · Confirmed-in-code**
Launch-at-login failure is silent. `GeneralSettingsViewController.swift:108-120`:
on `SMAppService` refusal the switch bounces back with stderr-only logging — no
error text, no announcement, no recovery suggestion (a test even pins the silent
revert as the contract). **Fix:** on catch, show an associated + announced inline
error ("Couldn't change launch at login — try System Settings › General › Login
Items"), via the SET-04 hint helper.

**SET-08 · Minor · 1.3.1, A7, B6 · Confirmed-in-code**
Theme tiles are not a radio group: no `.radioGroup` container/label ("1 of 3"
context missing), no arrow-key movement despite the announced radio role —
inconsistent with the real accent radios below.
`AppearanceSettingsViewController.swift:61-82, :153-168`. **Fix:** wrap in a
`.radioGroup` labeled "Theme"; arrow keys move+select; same treatment for Accent.

**SET-09 · Minor · B1, B5 · Confirmed-in-code**
No Edit menu (app-wide root at `AppDelegate.swift:914-934`; graded app-level as
SHL-01): in this window it kills ⌘C in the selectable About credits and ⌘V in the
Finder-chooser panel. **Fix:** the SHL-01 Edit menu.

**SET-10 · Minor · C6, 2.5.8 · Confirmed-in-code**
Excluded-row remove buttons have ~16 pt pixel-tight hit targets
(`AudioSettingsViewController.swift:658-686`; borderless `minus.circle.fill` at
12 pt, no size constraints). Saved legally by the spacing exception; fails the
house "padded hit areas" rule on the list's only destructive action. **Fix:**
`>= 24 pt` width/height anchors (no visual change); same for the Add row button.

**SET-11 · Minor · A2, 1.1.1 · Confirmed-in-code**
Decorative images exposed as unlabeled "image" elements: excluded-row app icons
(`AudioSettingsViewController.swift:650-653`), About icon (`AboutView.swift:135-145`) —
both redundant with adjacent text. **Fix:** `setAccessibilityElement(false)`.

**SET-12 · Minor · C4, C5 · Confirmed-in-code (thresholds need live confirm)**
Fixed-width value labels and fixed-height rows clip under ~1.3× text: 44 pt
percent label (`:257`), 56 pt "±N ms" label (`:596` — "−500 ms" already ≈50 pt at
13 pt), 34 pt `rowHeight` (`:137`), fixed 28 pt CTA row (`:477`). No
`preferredFont(forTextStyle:)` adoption exists anywhere to scale in the first
place. **Fix:** `>=`-style constraints; text-style adoption is the plan-level item.

**SET-13 · Minor · F5, H4 · Confirmed-in-code**
AX seams with zero assertions — including the documented blank-toolbar-slot trap
(no test asserts `NSTabViewItem.image != nil`), no per-control label assertions,
no visible-title-vs-AX-name consistency sweep (exactly why SET-02 shipped).
**Fix:** tab-image assertions + a generic "every titled button's AX name contains
its visible title" sweep over the three panes.

**SET-14 · Advisory · E3, 3.2.4 · Confirmed-in-code**
Wording drift: visible "Add app…" (`:702`) vs "Add application…" in two doc
comments and the popover's affordance. **Fix:** standardize on "Add application…".

**SET-15 · Advisory · HIG polish · Confirmed-in-code**
About version line not selectable/copyable (`AboutView.swift:151-153`). **Fix:**
`isSelectable = true` (pairs with the Edit menu fix for ⌘C).

### 3.2 Onboarding flow (ONB)

**ONB-01 · Major · A4, G4, E2 · Confirmed-in-code**
Zero VoiceOver announcements in an entirely asynchronous flow. Whole target has
no `NSAccessibility.post`; silent sites: `OnboardingViewController.swift:498-504`
(`refresh()`), `:513-534` (banner re-word/hide), `PermissionRowView.swift:222-272`
(accessory swap), `PTPHelperRowView.swift:122-161`. A VoiceOver user presses
Allow, answers the OS prompt in another process, returns — and hears nothing;
they must re-navigate into each row's accessory to discover whether the grant
took, four times over. **Fix:** diff-and-announce at each row's `update()`
choke point ("System Audio allowed", "…denied — Open Settings to fix", high
priority for denials); announce banner re-words and "All permissions restored";
share the popover's announce seam rather than duplicating it.

**ONB-02 · Major · B3, B7, G4 · Confirmed-in-code**
Every model change and every app re-activation tears down the accessory views,
dumping keyboard and VoiceOver focus. `PermissionRowView.swift:233` /
`PTPHelperRowView.swift:129` (unconditional teardown — `update()` has no
early-return on unchanged state), fan-out `OnboardingViewController.swift:498-504`,
trigger `SetupModel.swift:445` (`refreshStatuses()` fires `onChange` even when
nothing changed), called on every `didBecomeActiveNotification`
(`OnboardingWindowController.swift:84-91`). Pressing Allow destroys the focused
button immediately (probing flip); merely ⌘Tabbing away and back rebuilds all
four accessories and drops Tab position — and returning from the OS permission
dialog *is* a re-activation, so focus loss is guaranteed on every grant
round-trip. The window also steals key from any other app window (e.g. Settings)
on every activation. **Fix (three layers):** make `update()` idempotent
(early-return on equal `(status, isProbing)`); mirror the transition guard into
`refreshStatuses()` (the pattern already exists two methods down); on genuine
transitions, hand focus to the new accessory's first control and announce
(ONB-01).

**ONB-03 · Major · C1 · Confirmed-in-code (per-accent ratios worth a live measure)**
`ProminentButton` forces a white 13 pt title over the user-chosen system accent
in the key-window state (`PermissionRowView.swift:352`, fill `:327`, token
`Tokens.swift:79` = `controlAccentColor`). Approximate white-on-accent ratios:
blue ≈4.0, purple ≈3.9, pink ≈3.4, red ≈3.3, graphite ≈3.0, orange ≈2.2, green
≈2.0, yellow ≈1.6 — **every accent fails 4.5:1**, and on yellow/orange/green the
flow's primary CTAs are near-invisible. AppKit's own default buttons swap to dark
text on light accents for exactly this reason; the hand-rolled color defeats
that. (Non-key fallback and focus ring are fine.) **Fix:** derive title color
from the accent's relative luminance (formula already in
`OnboardingPermissionColorTests`), recompute on `viewDidChangeEffectiveAppearance`;
add the missing all-accents ≥4.5:1 sweep test.

**ONB-04 · Minor · A1 (A9-compatible fix) · Confirmed-in-code**
Three identical "Allow…" and two identical "Open Settings" buttons carry no
per-permission label (`PermissionRowView.swift:244-266`); FKA/VoiceOver users
hear "Allow…, button" ×3 with nothing distinguishing which OS prompt fires.
**Fix:** `"Allow \(content.title)"` / `"Open Settings for \(content.title)"` —
starts with visible text, so Voice Control keeps resolving.

**ONB-05 · Minor · A3, A6 · Confirmed-in-code**
Row speaks as disconnected fragments with identity and status each spoken twice
(`PermissionRowView.swift:406` — resting glyph labeled with the row title;
`:49-58` — status chip exposes image description *and* identical text). **Fix:**
chip image decorative; compose the row as an AX group (label = title, value =
status wording), children = detail + live buttons.

**ONB-06 · Minor · B2, G3, G4 · Confirmed-in-code**
"Continue Anyway?" sheet has no Escape/⌘. dismissal
(`OnboardingViewController.swift:575-591` — NSAlert auto-binds Esc only to a
button titled "Cancel"; buttons are "Go Back"/"Continue Anyway"). **Fix:**
`alert.buttons[0].keyEquivalent = "\u{1b}"` — Esc triggers the same safe action
Return does.

**ONB-07 · Minor · A1, A8 · Confirmed-in-code**
Probing spinner is an unlabeled progress indicator and, during the probe, the
row's *entire* accessory (`PermissionRowView.swift:144-147, :235-238`). **Fix:**
`"Checking \(content.title)…"` label.

**ONB-08 · Minor · B3, G3, G4 · Needs-live-confirm**
No initial keyboard focus seeded on present or re-front
(`OnboardingWindowController.swift:84-104`; no `makeFirstResponder` in target).
**Fix:** focus the first ungranted row's primary button in `present()`.

**ONB-09 · Minor · D1 · Confirmed-in-code**
Banner-clear window resize animates under Reduce Motion
(`OnboardingViewController.swift:527-533` — `setFrame(_:display:animate: true)`
unconditionally; contrast `IconTileView.setLit`, which guards correctly).
**Fix:** `animate: !accessibilityDisplayShouldReduceMotion`; the ONB-01
announcement fires either way.

**ONB-10 · Minor · C1 (§5-ledger process) · Needs-live-confirm**
Detail copy and non-terminal status words render `secondaryLabel` at ≈3.9:1 on
the warm light `panel` — the E6 payload (permission consequences) below 4.5:1,
on a surface with **no** §5 ledger entry (the ledger covers the Groups window
only). **Fix:** measure; lift to `labelColor` at reduced weight, or add an
explicit ledger row with the owner's decision.

**ONB-11 · Minor · F5, H4 · Confirmed-in-code**
Zero AX assertions in the onboarding suites; `ProminentButton` has zero tests
repo-wide; the real `beginSheetModal` path is untested (tests drive the stashed
confirmation only). No test-claimed behavior contradicts code — the gap is
one-directional coverage. **Fix:** per-state accessory-label assertions,
announcement-wording seam, ProminentButton contrast sweep.

### 3.3 App shell & entry (SHL)

**SHL-01 · Major · B5, B1, 2.1.1, G3 · Confirmed-in-code**
No Edit menu — clipboard/undo/select-all dead in every text field in the app.
`AppDelegate.swift:914-934` builds exactly two menus (App: Settings ⌘,/Quit ⌘Q;
File: Close ⌘W); no `cut:/copy:/paste:/selectAll:/undo:` item exists anywhere.
In AppKit these shortcuts are *menu key equivalents* — with no Edit menu they do
nothing. Real victims: Groups rename fields, icon-picker search, creation-sheet
name field. A keyboard user renaming a group cannot paste, select-all, or undo;
dictation/Voice Control "Paste that" drives the same dead selectors. Core task
"create/edit a group" is completable only by hand-retyping. **Fix:** standard
Edit menu targeting `nil` (~12 lines) + an F5 assertion that the main menu
carries the standard selectors. Update the stale AGENTS.md bullet (SHL-09).

**SHL-02 · Major · G1, A6, A9, A4 (+H1 drift) · Confirmed-in-code**
Status item: fixed "AirPlay volume" description — no app name, no state; doc
comment promises spoken/visual state channels that do not exist.
`StatusItemController.swift:128` vs `:29-41`; `StatusRoutingIndicator.swift:23`
(defined + fully unit-tested, **called from no production code** — the
documented routing dot is never rendered); `AppDelegate.swift:1346` (the arc is
fed the raw Main Out master — mute never reaches the controller, so a muted Mac
still shows "80% and broadcasting"). VoiceOver users get no app identity among
20 menu extras ("Click Audiouter" fails in Voice Control) and no
streaming/muted state — on the app's only closed-popover UI. **Fix:** compose
the description in `renderButtonImage()` ("Audiouter — streaming/muted/idle",
name first), thread mute in (drain the arc + append "muted", implementing the
documented contract), wire or delete `StatusRoutingIndicator`, move label
composition into pure `MenuBarStatus` for `MenuBarStatusTests` assertions.

**SHL-03 · Major · G2, B3, B1 · Confirmed-in-code (absence); consequence needs live confirm**
Popover summon/dismiss places no keyboard focus and restores none — every entry
path shares the gap. `PopoverController.swift:760-783` (`toggle` — activate +
show, no seeding; the only `makeFirstResponder` is the ↑/↓ `promoteFirstResponder`,
never on open), `:2581-2593` (`popoverDidShow/DidClose` — mouse monitor +
metering only). Keyboard users who open via Ctrl-F8+Space land in a key window
with nothing focused; on close, the app remains active with zero key windows —
keystrokes go nowhere; G2's "Esc returns focus to the status item" is
unimplemented. **Fix (one seam, all entry paths):** seed the first meaningful
control in `popoverDidShow`; on `popoverDidClose` with no remaining key window,
`NSApp.deactivate()` so system focus returns to the previous app; verify Esc
live and wire `cancelOperation` if the transient default doesn't cover it
(see POP-03).

**SHL-04 · Minor · G1, B1 · Confirmed-in-code**
Status-item secondary menu (Settings/Groups/Quit) has no keyboard or AX path:
it exists only inside the genuine-right-click branch
(`StatusItemController.swift:82-97`), assigned transiently; keyboard/AX
activation always takes the primary branch; no `accessibilityShowMenu`. Minor
because every destination is redundantly reachable (popover header buttons, ⌘,/⌘Q).
**Fix:** expose an `NSAccessibilityCustomAction` "Show menu" running the same
assign-performClick-clear dance.

**SHL-05 · Minor · B1 (SHOULD) · Confirmed-in-code**
No user-configurable global shortcut to summon the popover (verified absence of
any hotkey registration). Ctrl-F8 traversal is functional but slow and obscure.
**Fix:** opt-in configurable hotkey (Settings › General) invoking the existing
`onButtonClicked` path; Carbon `RegisterEventHotKey` is dependency-free and
D6-clean (registers one chord, swallows nothing else).

**SHL-06 · Minor · G5, A2, F1 · Confirmed-in-code (exposure needs live confirm)**
Decorative control-panel backing window is hidden from the mouse
(`ignoresMouseEvents`, defensive `hitTest`) but not from accessibility — no
`setAccessibilityElement(false)` in either file; it can surface as a second,
untitled, empty window in VoiceOver's window rotor. **Fix:** one line in
`makeBackingWindow` + a `test_backingWindow` AX assertion.

## 4. Compliant highlights (what already meets the gold standard)

Calibration: the audit found substantial *existing* gold-standard work — these
are the patterns the remediation plan generalizes rather than invents.

- **The device row's composed VoiceOver contract** (label = identity + membership
  + volume + connection + feed; value = live-signal words; hint = refusal
  reason; each channel spoken exactly once) with pixel-vs-speech lock tests
  (`AccessibilitySignalSweepTests`, `RouteArmedSignalTests`).
- **The energize announcement pair** — transition + honest settle tally, high
  priority, deliberately posted *outside* the Reduce Motion gate, wording
  test-pinned (`EnergizeTests`). The template for T1's fix.
- **Systematic Reduce Motion gating, re-derived at fire time and reconciled
  mid-session** via `accessibilityDisplayOptionsDidChangeNotification`
  observers with a `test_reduceMotionOverride` seam.
- **`DeviceIconWellView`** — a model hand-rolled control: first-responder,
  Space/Return, `accessibilityPerformPress`, focus-ring mask, RM-aware badge,
  64 pt target, every seam tested. The template for custom-control fixes.
- **`promoteFirstResponder(toAppRow:)`** — the proof that rebuild-preserving
  focus works in this architecture; it just guards one path instead of all.
- **Collapse semantics** (hidden body clips leave the AX tree and key-view
  loop; chevrons are real buttons with state-flipping labels), **creation-sheet
  key equivalents** (Esc/Return exactly right), **⌘,/⌘W/⌘Q on real menu items**,

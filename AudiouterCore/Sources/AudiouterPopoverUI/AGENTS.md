# AudiouterPopoverUI

## Purpose

The menu-bar popover UI (pure AppKit). `PopoverController` owns the `NSPopover`, builds the card stack, ingests `Device` snapshots via `update(devices:)`, and drives `GroupController`/`AppRoutingController`. Routing arithmetic lives in Core (see [../../AGENTS.md](../../AGENTS.md)); this folder only renders and turns clicks into controller calls. Shared row views live in [../AudiouterSharedUI/](../AudiouterSharedUI/).

## Rules

- Reacts only to `Device.connectionState` EDGES, not polling: `→ .failed` auto-expands its diagnosis panel once per episode; `guess → diagnosed` is the same episode and must not re-run cleanup. `→ .failed` does NOT drop the device from Selected Devices / a group (R12, W2-T3 — keep intent, always) — the silence watchdog covers audibility, and the backend auto-reconnects when the device GENUINELY comes back (a changed-descriptor re-resolve, a reappear-after-`disappeared`, or an engine good-state transition — since the 2026-08-06 storm fix a same-descriptor re-announce of a dead receiver deliberately does NOT re-kick; the user's "Try again"/re-toggle covers that case).
- Diagnosis panels auto-drive off `.failed` edges — `openDiagnosisIDs` is the open intent; a user ✕ records into `dismissedDiagnosisIDs` for the current episode, so no repaint/rebuild or mid-episode re-report resurrects a dismissed panel. A fresh `→ .failed` edge is a NEW episode: it clears the dismissal and re-expands. "Try again" is `GroupController.retryConnection` → `OutputBackend.retryOutput` — a single-device re-kick, never a membership edit and never a broad routing re-apply (a re-apply used to re-kick EVERY parked `.failed` id — the 2026-08-06 retry storm; a membership-neutral `setOutputSet` is no longer a retry). **The backend upholds the episode boundary**: its autonomous recovery (discovery re-kick on a genuine came-back edge, requeues) deliberately never emits `.connecting` for a `.failed` device — only user-initiated attempts (retry / toggle edge) and wake reconnects do — so a fresh `.failed` edge here always means a NEW deliberate attempt, and a dismissed panel can never be resurrected by background retry cycles. Don't "fix" the backend into showing a spinner for autonomous retries without revisiting this rule.
- **The open intent is ALSO pruned against MEMBERSHIP, not only against connection-state edges** (live bug, 2026-08-06). `.failed` is STICKY: deselecting a failed device produces no `→ .off` edge, so an edge-only rule left the panel mounted under a row the user had explicitly unselected, for the rest of the session. `handleConnectionTransitions` drops both intent sets for any id that fails `wantsAudio(_:)` (selected member OR app-redirect target — the same predicate `applySelectionState` uses for `controllable:`). This is the MIRROR of R12 above, not a breach of it: R12 forbids a FAILURE from dropping the user's selection; this drops the failure REPORT when the USER drops the selection.
- Every delegate callback mutates then calls `rebuild()`; rows aren't mutated in place after a structural change, except the refreshers used for mid-open repaints.
- Collapse state is keyed by the exact card header string — collapse calls must pass the same title the card was built with. The device-type SUBSECTIONS ("This Mac" / "AirPlay Devices" / "Bluetooth Devices") ride the identical `collapsedState(for:default:)` machinery under their own titles, so the two rebuild flavors below govern them too — but a subsection has no body to clip, so its toggle is a `rebuild()` that simply doesn't build the rows.
- **Two DISPLAY-only filters sit between the device snapshot and the rows: subsection collapse, and the per-device hide (`HiddenDeviceStore`, restored from the "+" menu).** Neither ever touches selection, membership or routing — the R12 spirit, and the reason a hidden device keeps streaming. ONE list expresses the result (`deviceSections()` → `renderedDeviceOrder()`) and `rebuild()`, `updateBusRailExtents` and `update(devices:)`'s structural-change test all read it: the rail terminus is the lowest selected VISIBLE node (otherwise the rows above it carry a through-rail to nothing), and the "did the device set change" comparison must be against what SHOULD render, never the whole fleet — comparing the fleet reads a deliberately-absent row as a permanent change and rebuilds on every backend event. A row that isn't built takes its sync drawer with it (`reconcileSyncDrawer` retracts the intent and stops the align tick) and its diagnosis panel — but the panel's open/dismissed INTENT survives untouched, so expanding/unhiding restores it iff the episode is still open. The empty-state copy splits for the same honesty reason: "Looking for devices…" only when there genuinely are none.
- Two rebuild flavors, not interchangeable: `rebuildForOpen()` resets collapse defaults, discarding this open's manual toggles; plain `rebuild()` preserves them.
- No `NSScrollView` — height flows through `preferredContentSize`. The card stack MUST stay pinned top AND bottom in `PopoverPanelViewController.loadView`, or Auto Layout collapses it to zero. **Surplus shield** (Alec's call, 2026-08-06): the popover sizes a WRAPPER (`view`), and the required-`==` content chain lives in `contentContainer` hanging from its top, with only a required `<=` between the two and deliberately NO pull-tight pin. `fittingSizeSettled` measures `contentContainer`, never `view`. This shape is forced, every alternative measured: a required `==` straight to the sized view makes an over-tall popover unsatisfiable and Auto Layout deforms the CONTENT (the ballooned banner in the live report); a `<=`-only pin makes `fittingSize` return stale frame heights (it does not minimize to the floor — a collapsed card kept reporting the expanded height); and a soft `==` has no workable priority — `fittingSize` ignores it below ~500 while anything ≥251 out-prioritizes the banner label's 250 hugging and stretches the banner again. With the shield, an over-tall popover degrades to inert warm canvas below the last card, rows hold their geometry, and the rail stays anchored.
- **`insertRow`/`removeRow` own the re-fit; callers must NOT add their own `panelContentDidChangeHeight`** (live bug, 2026-08-06). `removeRow` defers its detach into an `NSAnimationContext` completion handler, so a caller-side re-fit measures a row that is still in the tree and about to leave — and nothing measures again once it does. The popover then stays taller than its content, one row's worth per removal. Because the stack is pinned top AND bottom (rule above), that surplus has to go somewhere Auto Layout isn't pinning: in practice the pinned banner, which balloons into a tall empty box and pushes every card below it down. Any future row primitive that mutates the stack republishes the size itself, from wherever the mutation actually lands.
- **A row's VISIBILITY has to be true before its height is measured, not a consequence of the animation that follows** (live bug, 2026-08-08 — "the sync drawer opens from the top of the screen after the first time"). An `NSStackView` gives a hidden arranged subview zero height, so `insertRow` measuring a row that arrives hidden publishes a size with the row left out: the popover is told "no change", the content grows underneath it, and the panel only catches up on some later unrelated re-fit — one disconnected lurch instead of the row opening. A REUSED row does arrive hidden, because `removeRow`'s animated path hides the view and never un-hides it, and the BT sync drawer is a single instance re-parented across rows (D2) — hence hidden on every mount after its first, which is exactly why the FIRST expansion behaved and no other one did. `insertRow` therefore sets `isHidden = false` before it measures. The same line is what keeps Reduce Motion working: that path returns before the reveal animation, so a row left hidden there would mount invisible for good. Row reveal/collapse share ONE duration (`rowRevealDuration`, 0.15s) so an expand and its collapse are mirrors. **And the reveal's START state must be LAID OUT before the animation begins, not merely set** (live feedback, 2026-08-08 — "collapsing smooth, expanding abrupt"): measuring the row for `preferredContentSize` runs `layoutSubtreeIfNeeded`, which commits every row below it to its FINAL position, so re-hiding the row without a second layout pass leaves the animation nothing to travel — `animator().isHidden` interpolates from the frames currently laid out. Measured: gap 0 → 72 after measuring → still 72 after hiding → 0 only once the hide is laid out. Collapse never had this because nothing measures it into place first, which is precisely why only expand read as abrupt.
- **The popover is the ONLY host of `PopoverPanelViewController`, in dev AND in the shipping `.app`.** `AIRPLAY_CONTROL_PANEL=1` (baked in by `scripts/make-app.sh`) re-homes **Groups** into `ControlPanelWindowController` and nothing else — `presentInControlPanel` is called once, with `MixerWindowController.contentController`. Don't chase a popover-surface bug (row heights, the sync drawer, card collapse) into the panel shell's window geometry; `NSPopover` keeps its own top edge pinned to the status item and grows downward on its own.
- `ConnectionDiagnosisView` never touches `NSPasteboard`; the host writes on `onCopyDetails`.
- `selectedAppBundleID` is host-owned, transient. All three removal entry points (± footer, "Remove from list", Delete/Backspace) must funnel through `removeApp(bundleID:)`.
- The Applications card's add/remove control is `ApplicationsFooterView` (± `NSSegmentedControl`), replacing the old "+ Add application…" row.
- `PopoverController.updateLevel(_ rms:, for id:)` is the live push path from `AppDelegate`'s `.level` handling: it early-returns when the popover `isShown` is false, so a backend still emitting behind a closed popover doesn't do wasted view work. `test_pushLevel(_:for:)` is the same dispatch WITHOUT the `isShown` gate, for headless snapshots/tests that never actually show the popover. Both route to `deviceRowsByID[id]?.setLevel(rms)` and, for the Main Out id, `mainOutRow.setLevel(rms)`.
- `PopoverController.updateAppLevel(_ rms:, for bundleID:)` mirrors `updateLevel(_:for:)` for the Applications card: same `isShown` gate, same gate-free test twin (`test_pushAppLevel(_:for:)`), both routing to `appRowsByBundleID[bundleID]?.setLevel(rms)`. Unlike a device level, an app level never feeds `mainOutRow` — Main Out mirrors the selected DEVICE's level, not any one app's contribution. `makeAppRow` constructs its `AppRowView(showsMeter: true)` so the row actually has a meter to push into.
- Closing the popover zeroes every meter rather than leaving a stale bar: the close path calls `resetLevel()` on every row in `deviceRowsByID`, on `mainOutRow`, and on every row in `appRowsByBundleID`.
- Metering itself is gated off the wall-clock cost of RMS computation while the popover is closed: `PopoverController` drives `(backend as? MeteringControlling)?.setMeteringActive(_:)` — on when the popover opens, off when it closes — so the backend only computes RMS (and only runs the metering-only taps) while there's a UI to show it to.
- **Energize (item 9)** is orchestrated here, drawing-only. `mainOutRow(_:didSelect:)` (the source-switch delegate) calls `beginEnergize(to:)` before `rebuild()`: it posts the VoiceOver transition announcement (always — the announcement is independent of Reduce Motion) and, unless Reduce Motion is on, seeds `energizePendingIDs` with the SELECTED members still `.off` — the rows the left rail already runs through, so the clean cases (switch to Selected Devices / a derived-identity group) light their spine while a genuinely-diverging group target stays dormant (§4.7). `refreshDeviceRows()` calls `reconcileEnergize()` first: it prunes the beat off members that have left `.off` (their model node takes over) and fires the one-shot settle announcement once the target stops moving. No timers — the top-to-bottom fill rides the live `connectionState` progression (each member's own connect-brighten is the per-row `DeviceRowView` cross-fade, item 8). Hooks: `test_switchMainOut`, `test_setEnergizePending`, `test_energizePendingIDs`, `test_energizeActive`, `test_lastEnergizeAnnouncement`, `test_reduceMotionOverride`.
- **Every device-type subsection is HIDDEN entirely when it has no rows to show** — never an empty grouping label — whether that is "no BT device exists" (BT-UI) or "the user hid them all". Bluetooth rows are recency-ordered (`lastUsed` via `btLastUsedProvider`; ghost pairings sink to the bottom, sort-only). The OUTPUT DEVICES "+" fronts a MENU now ("Save Selected Devices as group" + "Pair a Bluetooth speaker…"): `canSaveCurrentSetup` gates the save ITEM, the button itself stays always-enabled so pairing is always reachable; the on-screen `popUp` is `HeadlessRuntime`-gated (it blocks), tests dispatch via `NSMenu.performActionForItem(at:)`.
- **The align-by-ear tick is host-owned lifecycle, backend-owned audio** (BT-OFFSET-UI): one row at a time, ~30 s auto-stop, and `popoverDidClose` always stops it — the tick must never outlive the surface that started it. Since PLAN-BT-SYNC-DRAWER the tick's button lives INSIDE `BTSyncDrawerView`, so collapsing the drawer must stop it too: a metronome ticking with no visible control is a bug. Trim edits cache in `btTrimsByID` (freshest-edit-wins over `btTrimProvider`), so a repaint can't revert a user's nudge.
- **At most ONE sync drawer is open at a time** (PLAN-BT-SYNC-DRAWER D2), and there is ONE reused `BTSyncDrawerView` instance, not one per row — the drawer is ~3 rows tall, so several open at once would swamp the popover. `expandedSyncDeviceID` is the single owner; opening another device collapses the first. Mount and unmount ONLY through `insertRow`/`removeRow` (they own the re-fit — see the rule above). TRAP: `removeRow` defers its detach into an animation completion handler, so re-parenting the one shared drawer under a different row made that deferred detach fire against a stack the view had already left, throwing `NSInternalInconsistencyException`; `removeRow` now guards on `superview === stack`, and a drawer that MOVES between rows detaches un-animated so two animation groups never fight over one view's `isHidden`.
- **A live scrub applies to audio but must NOT persist.** `syncDrawer(_:didChangeTrimMs:committed:)` carries the split: `committed == false` writes audio only, `committed == true` writes audio AND the JSON store. Without it a drag would rewrite the store dozens of times a second. Every committed value goes through `BTSyncTrim.quantise` so the readout, the ruler and the saved value cannot disagree. "Not set" is decided by whether the store HOLDS an entry, never by the value being zero — a device deliberately tuned to 0.0 is tuned.
- **A selected BLUETOOTH device that loses availability is DESELECTED here, on the edge** (Alec's call — off = unselected; this replaced a backend-side power-off park): `update(devices:)` diffs availability against the previous snapshot and routes the loss through `GroupController.setDeviceSelected`, the one selection owner — the mirror of `handleDeviceDisappeared`'s route reset. EDGE-only on purpose: a selection made on an already-greyed row ("play when up") has no edge and must survive, and a `.failed` story alone never deselects (R12) — only the availability fact does. This is deliberately the OPPOSITE of the AirPlay rows' keep-intent rule in the bullets above; don't "unify" the two.
- Known stability findings in this target carry `STABILITY(id)` inline markers — details and fix sketches in [../../../dev/notes/stability-audit-2026-07-18.md](../../../dev/notes/stability-audit-2026-07-18.md).

## Map

| Type | What it is |
|---|---|
| `PopoverController` | Orchestrator: `NSPopover`, cards, `Device` ingestion. |
| `PopoverPanelViewController` | Card container: build/collapse by header title. |
| `CardView` | Rounded module: header rows + collapsible body. |
| `MainOutRowView` | System Audio "Main Audio" row — slider, mute, "Output" destination dropdown, under-name `LevelMeterView`, and the membership rail's `.origin` hook (rises in the left gutter and turns into the meter). |
| `ConnectionDiagnosisView` | "Couldn't connect" panel under a failed row. |
| `PopoverHeaderView` | Top bar: title + groups / settings / quit. |
| `GroupRowView` | Group's master row; built for the window, unused here. |
| `RunningAppInfo` | Snapshot of a running app for the add picker. |

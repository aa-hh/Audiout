# Review of the Settings redesign diff (2026-10-07)

Reviewer verdict: not approved. Four findings, one honesty note. Paths are relative to the worktree root.

1. `AudioutCore/Sources/AudioutSettingsUI/SettingsSidebarViewController.swift:127` and `:280-284` — `setReadout` rebuilds the row's cell with `outlineView.reloadItem(node)`; the rebuilt cell has no superview yet, so `makeSectionCell` inks it as unselected (`selected: false`), and nothing re-inks it afterwards: `reloadItem` keeps the existing `SidebarRowView`, so neither `isSelected`'s `didSet` nor `didAdd` fires. Every readout push on the selected row (every Settings open through `SettingsRootViewController.viewWillAppear` → `refreshReadouts`, every Launch-at-login toggle, every key entered on the License pane) leaves the selected row's name, glyph and readout in `Tokens.Color.label`/`labelCool` on the accent pill until the user changes selection or the window loses and regains key. The Speakers sidebar avoids exactly this (`AudioutWindowUI/SidebarViewController.swift:899-905`: "Never through `reloadItem`/`reloadData`, which would rebuild the rows") and reconfigures the live cell in place. Step 11(e) prescribed `reloadItem`, so this is a spec defect carried into the code; it still needs fixing.

2. `AudioutCore/Sources/AudioutSettingsUI/LicenseSettingsViewController.swift:333-338` — `viewWillAppear` only calls `revalidate()` when `licenseStatus == nil`; it never calls `refreshLicenseStatus()`. The header caption (`:285`), the status sentence, the button title and Buy visibility are all computed from `TrialClock.state(settings:)` and are set only when the pane first loads or a sheet/validator event fires, while the sidebar readout is recomputed on every show (`SettingsRootViewController.swift:116-119`). Scenario: a trial user opens License on day 5, then opens Settings › License again after midnight or after the trial ends. The sidebar row says "Trial · 8 days left" or "Trial ended" and the pane header beside it still says "Trial · 9 days left" and "Audiout plays on every speaker until your trial ends on …", with "Enter license…" where "Change…" and the one-speaker sentence should now be.

3. `AudioutCore/Sources/AudioutApp/AppDelegate.swift:217-222` and `:652` — `generalSettingsController` is still stored (`:2511`) but no longer read anywhere, and the comment above it still says the weak references "exist only so `audiout://register` can reach the license sheet"; `:652` still says "Bring up Settings ▸ General with the license sheet open". Both describe the pre-diff wiring.

4. Departure (6), assessed: compliant with the work order's step 14, but it changes what a user sees. Before, General was mounted on every Settings open and its `viewWillAppear` re-asked the server about an unanswered key; now that happens only when the user clicks the License row. An unanswered key (`licenseStatus == nil`) is not "limited" (`LicenseGate.swift:47-52`), so the Mixer-open revalidation at `AppDelegate.swift:1463-1468` does not cover it either; only launch (`:1009`) and the License pane do. "Key saved, not verified" now persists across Settings opens until the user visits License or relaunches. The Mixer's licence note is unaffected (`applyLicenseState` reads settings, and a nil verdict yields no note).

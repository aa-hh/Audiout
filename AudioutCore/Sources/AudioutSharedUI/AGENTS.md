# AudioutSharedUI

## Purpose

AppKit row views shared by the popover (`AudioutPopoverUI`) and the Groups screen (`AudioutWindowUI`) so both hosts render the same device row from one implementation. Views here are pure UI: controls route out through a per-view `Delegate` (or closure), never touching a backend, store, or `GroupController` directly. For the routing model these rows render, see [../../AGENTS.md](../../AGENTS.md).

SharedUI also hosts shared WINDOW CHROME, not only row views: `ControlPanelWindowController` is the sticky floating-panel shell that IS the one surface's window (the shell always ships; `AppSurfaceController` in `AudioutPopoverUI` owns it and swaps the Mixer/Groups/Settings screens through it). It stays content-agnostic: one panel, content swapped via `setContent(_:)`; it knows nothing about groups, devices, or settings — callers own their own content `NSViewController` and push it in.

## Rules

- Views never read shared model state — hosts push a plain-value snapshot via `apply(...)`. `DeviceRowView` takes `selected` explicitly (membership lives in `GroupController`, not `Device`); `AppRowView` takes an isolated `Configuration`.
- Row geometry lives in `PopoverColumnGrid` (named constants, no magic numbers) — columns anchor to the row's *trailing* edge, so slider/status/trailing-control columns line up across sections despite different leading controls.
- Hover state is transient, separate from selection, reconciled via an app-local `.mouseMoved` monitor cleared on every `apply` — an `NSTrackingArea` alone never fires `mouseExited` for a bottom-most row with an untracked dead-zone below it.
- `DeviceRowView` computes `isInMenu` live from `enclosingMenuItem` to pick its drawing path and accessibility role — don't hardcode one path for both hosts.
- `DeviceRowView.draw(_:)` and `AppRowView.draw(_:)` are drawing-only row backgrounds: stack-hosted rows (popover card / mixer window) get no system row chrome, so each paints its own inset rounded selection/hover pill (unified `PopoverColumnGrid` alphas), and a menu-hosted `DeviceRowView` must paint the menu highlight itself — AppKit draws no background behind a custom menu-item view.
- A row's contextual menu rides AppKit's `menu(for:)` seam so right-click and VoiceOver's "show menu" share one path. The row icon is the same menu's click trigger (`MenuTriggerImageView`), inert only when the menu would be empty. Don't hand-roll `rightMouseDown` beside it.
- Each view exposes `test_*` hooks (`test_setVolume`, `test_toggleEnabled`, …) that must drive the exact same delegate path as the live control, since gestures can't be synthesized headlessly.
- The device row's trailing control is an `NSButton` checkbox under a "Selected" header (membership in "Selected Devices"), not an `NSSwitch`; the column is not "Enabled".
- `DeviceRowView.apply` takes `controllable` separate from `selected`: slider/mute enablement follows `controllable`, but the checkbox and the sublabel's "System" token follow `selected` alone.
- **The membership checkbox's enablement is intent-derived: `isAvailable || selected`.** A stuck-`.failed` row must stay deselectable even though it's unavailable, so a selected row always keeps a live toggle; slider/mute stay availability-gated.
- The popover header's icon buttons are stock `NSButton` (`bezelStyle = .accessoryBar` with `showsBorderOnlyWhileMouseInside = true`) — no custom hover-button class exists here.
- `DeviceRowView`/`AppRowView` take `showsMeter: Bool` and host the Warm-Signal `LevelMeterView` inside a vertical `identityStack` under the name, shown only on armed rows; the stack recentres its own lines.
- `LevelMeterView` is a short horizontal warm-gradient bar (ember→gold→caution) whose fill width tracks level. `caution` is the ceiling — failure red must never appear in a meter (house rule 8).
- `RouteArmedDotView` is PURE MODEL STATE, never RMS: `routeArmed = (inActiveTarget ∧ connected ∧ !muted) ∨ liveAppNames≠∅`, computed in `apply`. The gold bloom fires only on a false→true transition after the first apply — the model layer stays settled so snapshots stay deterministic.
- A muted row's chrome is `Tokens.Color.engagedChrome` — NEUTRAL, never gold or the system accent (gold means signal; a gold mute states the opposite). The glyph never swaps to a slash (locked). The "MUTED ·" sublabel token appears only when a sublabel already exists, so row height never changes.
- `BusRailOverlayView` reads its section adapters' live clip frames every draw and resolves geometry through the pure `RailPlan.resolve`. TRAP: invalidation must hang off a view that re-lays out when the ROWS move, not the top-level container — a container's `layout()` doesn't fire when only descendants relayout. Never dirty from `viewWillDraw()` — that schedules a display pass every pass, forever. Both `RailSectionProviding` properties are `weak`; a host-built adapter must be retained by the host.
- The rail is ONE stroked wire (no channel/pad/recess) — gold while armed, ember idle, `railDormant` end-to-end when dormant, running to the lowest on-spine node only. Dormancy is ONE flag for the whole rail, never per-stop — per-stop dimming reads as a patchwork on a wire feeding nothing.
- The node's click target and hover ring are the SAME rect (`PopoverColumnGrid.busHitTargetWidth` × full row height) — one rect for both. It stops `busHitTargetIconGap` short of the icon column because AppKit's rounding grid varies per run, so a box computed to land exactly on the icon's edge lands under it half the time.
- The "Removed — Undo" offer is HOST state; `DeviceRowView.apply(removalUndoOffered:)` is drawing-only, borrowing the empty trailing slot so it costs no reflow. Undo reports `deviceRowDidRequestUndoRemoval` only — the re-add is the host's checkbox path.
- The left gutter width (`busGutterWidth`) is DERIVED from the rail geometry, so widening the rail only reflows LEADING columns — trailing-anchored VOLUME/OUTPUT columns hold.
- A trimmable row's SYNC control (Bluetooth rows, and the Mac's own row) occupies the trailing slot only, never the shared grid. The chip (`syncChipButton`/`SyncChipCell`) is READ-ONLY — it reports `didToggleSyncDrawerFor` and never edits or clamps a trim; all editing lives in `BTSyncDrawerView`. The chip's number is the TOTAL (measured latency + trim), not just the trim — printing only the trim reads "0 ms" the instant a wizard run finishes even though the speaker still carries that latency, and it does not clamp even outside the trim's own range. TRAP: the failed feed pill must render `ConnectionFailure.headline`, never a hardcoded string. TRAP: `BTSyncDrawerView.configure` never overwrites a live edit — an external trim change must go through `noteExternalTrimChange(_:)` or the drawer's next gesture silently overwrites the new measurement. "Reset alignment" DELETES the stored latency+trim; Revert only restores the drawer's pre-edit value — they are not twins.
- A greyed Bluetooth row's name click CONNECTS, never selects (checked before the checkbox-enabled guard — a disabled checkbox IS the greyed case). A BT reconnect pairs `.connecting` with `isAvailable == false`, so the connecting node must stay visible and the "Unavailable" pill suppressed mid-attempt.
- Any animated/token-colored instrument (`HaloRingView`, `RouteArmedDotView`, `WarmCanvasView`, `LevelMeterView`, `EQResponseCurveView`, `DeviceRowView`) must observe `NSWorkspace.accessibilityDisplayOptionsDidChangeNotification` directly — a mid-session Reduce Motion/Increase Contrast/Reduce Transparency toggle arrives through neither `apply` nor `viewDidChangeEffectiveAppearance`. Reduce-Motion reads go through `test_reduceMotionOverride` for headless tests.
- `Tokens.accentStyleDidChangeNotification` (posted from the dial's `didSet`) is a THIRD live re-resolution trigger a layer-color instrument must observe — a `draw(_:)` instrument just needs invalidation, but one that stamps a resolved `CGColor` onto a `CALayer` needs to re-stamp on this notification too.
- The rail's hook, its `.member` segments, and the Main Audio ring all take their tone from ONE function, `Tokens.Color.spineTone(armed:)` — two call sites naming `gold`/`ember` separately is what let the accent dial move one and not the other. Device rows' own ring stays hue-neutral (`ringConnected`) and must never be pulled onto the dial.
- TRAP: `CALayer.add(_:forKey:)` ignores a custom key for `CATransition` — it's always filed under the literal string `"transition"`, unlike `CABasicAnimation`. Look it up/cancel by that reserved key.
- `DeviceRowView.apply(energizePending:)` is DRAWING-ONLY (the Main-Audio source-switch "press-play" beat) — it never touches the model; the `.off` guard in `updateBus()` means a real `connectionState` change supersedes it automatically. Gated on Reduce Motion.
- `WarmFaderCell` is a drawing-only `NSSliderCell` swap (tracking/keyboard/VoiceOver/focus stay stock) — the swap must happen FIRST in `buildSubviews`, before target/action config. Its gold fill renders ONLY under the exact same route-armed predicate as `RouteArmedDotView` — one armed truth, two instruments. `GroupRowView`'s master slider and the Settings connect-volume slider deliberately stay stock — don't extend the skin to them.
- `WarmNameFieldCell` is a drawing-only `NSTextFieldCell` swap (same contract as `WarmFaderCell`) — swap the cell before configuring the field. Text insets must go through `drawingRect(forBounds:)` ONLY — that's the one seam AppKit routes both the drawn string and the field editor's frame through; overriding `select`/`edit` too would inset twice.
- `SidebarWarmSurfaceView` backs both source-list sidebars — they must stay PLAIN split items; a `.sidebar`-behavior item makes AppKit reserve the toolbar's leading region. Draws its own opaque warm backing by default; Reduce Transparency always wins to the opaque backing.
- **ControlPanel shell (`ControlPanelWindowController` + `ControlPanelBackingView`):**
  1. Two-window shell: the real content panel keeps `.titled`/`.closable` in its style mask (removing them silently breaks `performClose` — it no-ops with no `windowWillClose`) even though it's made visually borderless. A second, click-through decorative `NSWindow` (`backingWindow`, `ignoresMouseEvents = true`) sits behind it drawing the bubble+beak and owning the shadow.
  2. `setPinned(_:)` flips manner/appearance only, never the style mask — `.titled`/`.closable` must survive both profiles or Escape/`onClose` break. `isFloatingPanel` IS the level switch (writes `level` itself); `.resizable` is the one mask bit a caller does flip, orthogonal to pin.
  3. TRAP: the status-item click resigns key BEFORE the button's action runs — the click handler must call `consumeRecentResignDismissal(within:)` before reopening, or the panel can only flicker, never toggle shut. A live sheet suppresses the dismiss; an app-switch resign is a tuck-away, not a close.
  4. `show(anchorRect:)` must read the panel's frame back AFTER `makeKeyAndOrderFront`, never before — AppKit can silently re-constrain a window's position to the screen's `visibleFrame` the instant it's ordered on screen.
  5. Reassigning `window.contentViewController` is NOT size-neutral — AppKit resets the window to a (500,500) fallback the instant any view controller is (re-)assigned. `setContent` must capture the panel's size BEFORE reassigning and restore it right after, on every re-host.
  6. `setContent`'s `defaultSize:` seeds size only on a controller's genuine FIRST mount (by `ObjectIdentifier`) — the deliberate OPPOSITE of `AudioutSettingsUI`'s "re-measure before every show" rule: this panel is user-resizable and a dragged size should hold for the process's life. Don't unify the two.
  7. `addChildWindow` tracks the parent's translation automatically but never its size — `windowDidResize` must re-run the backing-window lockstep by hand on every panel resize.
  8. Open/close is a plain opacity fade, flattened under Reduce Motion — never a transform/slide (that would need to animate caller-owned content's layer this shell doesn't control). `onClose` must keep firing synchronously from `windowWillClose` — the real close is never deferred to let the fade finish.
- The device row's VoiceOver contract is ONE composed announcement: label = identity + membership + volume + connection clause, value = the live-signal words (`muted` / `armed` / `playing here`), hint = the blocked-row refusal reason — each channel spoken exactly ONCE, never duplicated across label/value.
- `DeviceIcon` is the single resolution point for "what SF Symbol represents this device/group" — `DeviceIcon.resolve(_:default:)` falls back to the kind/group default when an override is `nil` or no longer resolves on this OS (`DeviceIcon.isValid`). `DeviceIconController` is the only place a per-device icon override is looked up or written (`AudioutCore.DeviceIconStore` persists it); only the bare symbol name string is ever persisted, never a resolved image or a color.
- `InvisibleSwitchCell` is shared, not duplicated — the Groups window's membership checklist reuses the same `public` implementation as `DeviceRowView`'s popover rows.
- `.raised` + `.hairline` form the Groups screen's ONE card: a `GroupedSectionView` in `.card` mode fills `.raised` and strokes a 1 pt `.hairline` edge; `.hairline` alone draws the inset dividers of every other list, which are `.bare`. On dark, `.raised` on `.panel` is only 1.07:1, so the card's edge carries its separation.
- `ControlPanelBackingView` is an APPROVED custom-drawn exception to the "stock components only" house rule (root `AGENTS.md`): NSPanel has no built-in arrow/notch, so tying the control-panel shell visually to the menu-bar status item requires custom drawing. All of it is confined to this one view.

## Map

| Type | What it is |
|---|---|
| `DeviceRowView` | Shared device row: icon, name/sublabel, mute, slider, %, Selected checkbox; optional leading `LevelMeterView` via `showsMeter`. |
| `MenuTriggerImageView` | Icon that pops its host row's context menu; AX button only while armed (`onPress != nil`), a plain image otherwise. |
| `EQEditorView` | Tone editor hosted by the Groups detail panes: Bass/Treble/Balance/Loudness + Advanced section; `apply(eq:bypassReason:)` in, `EQEditorViewDelegate` out. |
| `EQResponseCurveView` | The scope inside the Advanced fold: custom-drawn instrument, pure `Plan`, `bandCentreX` is the shared x-axis the faders sit on. |
| `LevelMeterView` | Shared under-name VU bar (short horizontal, warm gradient fill, ballistics-driven, non-interactive). |
| `MembershipBusView` | The membership checkbox's DRAWING-only skin: the left-spine rail + node. Non-interactive — the real `NSButton` stays the control. |
| `HaloRingView` | Connection halo ring around the device icon, driven off `Device.connectionState`. Also owns the rail connect pulse's acknowledgment (`receiveRailPulse()`). |
| `RouteArmedDotView` | The gold route-armed corner dot: pure model-state "route armed & held" lamp on the icon's corner. |
| `PopoverColumnGrid` | Shared column-geometry constants (rail gutter, under-name meter, fader geometry, inline rename field, edit-affordance alphas). |
| `WarmNameFieldCell` | The inline-rename skin (Groups window header): drawing-only `NSTextFieldCell`. |
| `WarmFaderCell` | The Warm Signal fader skin: drawing-only `NSSliderCell` swap on the row volume sliders. |
| `AppRowView` | Popover-only per-app row; owns its own selection highlight and hover wash. |
| `DeviceIcon` | Single resolution point (+ curated symbol list) for device/group icon names, with render-time fallback. |
| `DeviceIconController` | Loads/persists per-device icon overrides via `AudioutCore.DeviceIconStore`. |
| `ControlPanelWindowController` | The one surface's window shell: `NSPanel` in one of two manner profiles (`setPinned(_:)`), one-panel-at-a-time via `setContent(_:)`. |
| `ControlPanelBackingView` | The approved custom-drawn exception: rounded bubble + beak triangle tying the shell to the status item. |
| `ReduceTransparencyFallbackView` | Opaque cover installed inside content-bearing `NSVisualEffectView`s; shown exactly while Reduce Transparency is on. Install BEFORE the content subviews. |
| `WarmPanelView` | The one surface canvas: flat opaque `panel` fill, draw-time token resolve. |
| `MenuBarStatus` | Pure, AppKit-free idle-vs-streaming decision for the menu-bar status item. |
| `StatusItemIcon` | Builds the status item's `NSImage` from `MenuBarStatus.symbolName` — always a template image. |
| `Tokens` | The root AGENTS.md's sanctioned custom-palette exception: `Tokens.Font`/`Layout`/`Material` forward to existing semantic values; `Tokens.Color` adds the warm surface ladder + hairline and the alignment-wizard stage instruments. |
| `WarmCanvasView` | The Warm Signal gradient+grain canvas, used by the Setup window and the alignment wizard sheet. `WarmSignalGrain` is the grain tile generator, deterministic by construction. |
| `SurfaceLayout` | The one surface frame's fixed width plus the sidebar numbers the Groups and Settings sidebars share. |
| `SidebarWarmSurfaceView` | Non-interactive warm wash behind both source-list sidebars' outline views. |

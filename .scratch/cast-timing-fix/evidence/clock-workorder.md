# Work order: one clock for the Cast feed's timing stamps

All paths below are in `/Users/alechenderson/Projects/AirPlay Controller/.claude/worktrees/cast-timing-fix-r2`. Line numbers are against the WORKING TREE there (uncommitted `CastSincResampler` work included).

## Goal

Every timestamp the Cast feed ring subtracts from another is read on the raw mach tick clock (`mach_absolute_time` through the timebase, the same thing Core Audio's `mHostTime` is), so the time daemon `timed` steering `CLOCK_MONOTONIC` (12 to 30 ppm creep, plus 5 to 35 ms ramps every 17 to 29 minutes, measured 2026-10-06) can no longer show up as a phantom change in `age_ms` and `ioproc_to_push_ms`, which `holdMs` feeds into Cast speed matching and which then moves the TV for real (+100 ppm pinned, 14 to 48 ms). `ioproc_to_push_ms` becomes the block-level push lateness, and the once-a-second telemetry gains two per-second maxima so real scheduling lateness under load is visible. The AirPlay, Bluetooth and synced Mac sinks keep receiving exactly the `pts` they receive today.

## Decisions made here

1. One clock = raw mach nanoseconds through `CoreAudioSystemTap.machNanoseconds(fromHostTime:)`. The ring's "now" is `Int64(CoreAudioSystemTap.machNanoseconds(fromHostTime: mach_absolute_time()))`, the identical arithmetic the capture side uses, so rounding matches.
2. `pts` keeps its meaning for every consumer. The Cast sink is handed, beside the unchanged `pts`, the block's capture time in raw mach nanoseconds (`captureNanos: Int64`). Non-Cast paths are byte-identical.
3. The coordinator learns the tap's frozen offset from each real tap buffer (`ptsNanos − machNanos`) and uses it to rebase the three synthetic producers (wizard pacer, leveled clock, gap fill) onto the raw clock, so a wizard run or an idle-tap fallback still gives the ring consistent stamps.
4. `ioprocToPushMs` becomes `pushedAt − captureNanos` of the block (no in-block offset, no delay term). `ageMs` keeps its per-frame definition. The identity changes to `ageMs == ioprocToPushMs + delayLineMs + ringWaitMs − (the rendered frame's offset into its block)`; the doc and tests say so rather than adding a field for the offset.
5. Two new maxima, covering the span since the last `timing` read (the status poll reads once a second): `ioprocToPushMaxMs` (producer side) and `ringWaitMaxMs` (consumer side). Telemetry names: `ioproc_to_push_max_ms`, `ring_wait_max_ms`. No existing field renamed. Both reset when `timing` is read.
6. Fix 3 (queue priority, allocation hoist) stays out.

So a `timed` slew or step moves the sync packet's "play at" time relative to the clock the receiver trusts, and an AirPlay receiver that honours sync packets would re-time by that amount (24 ms tonight). Whether a given receiver audibly re-times on a 24 ms sync shift was not verified; the report's `send_sched` and `write_cadence_drift` (both `CLOCK_MONOTONIC_RAW`, `AirPlayEngine.swift:2133`, `:2534`) cannot see it. The fix there would be the opposite direction from Cast: make the timing and PTP responders answer on the pts clock, inside vendored C, so it is a separate, ledgered follow-up.

## Fix-list appendix (from review; OVERRIDES decision 3 and steps 5–6 above)

Defect: `castClockOffsetNanos` (seeded at init, refreshed only by real tap buffers) goes stale for the three synthetic producers (wizard pacer, leveled-app fallback clock, `fillFeedGap`). A leveled-only session, or any session after sleep with no real tap buffer, hands the Cast ring a `captureNanos` that carries all of `timed`'s steering since the last refresh (or the sleep length), which reaches the hold and speed matching — the exact symptom this order removes.

Ruling: NO cached offset. Remove `castClockOffsetNanos` entirely (its declaration, the init seed, the `handleBuffer` write and its doc comment).

F1. `deliver(_:pts:snapshot:…)` gains a parameter `captureNanos: Int64` (0 = "none, derive it"). The real tap call site in `handleBuffer` passes `Int64(buffer.machNanos)`. The three synthetic callers (wizard pacer, leveled fallback, `fillFeedGap`) pass 0.
F2.
